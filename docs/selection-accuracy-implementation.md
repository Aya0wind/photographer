# 清晰度与闭眼：工程接入与验证边界

实现对应 [升级方案](plans/2026-10-08-selection-accuracy-upgrade.md)。当前采用用户指定的固定 1024 缓存图方案，保留区域结果、专用闭眼候选和失焦模型评估接口；**没有摄影标注集，因此尚未完成准确率校准或正式模型替换**。

## 当前应用行为

- 选片分析统一使用已生成的固定长边 1024 像素缩略图，不随画质档位读取原图或显影 RAW。缓存命中时用数据库修改时间定位本地文件，不访问 NAS 原文件元数据；缓存缺失时才按需生成 1024 档（RAW 仅提取内嵌预览）。
- 固定使用 1024，不尝试其他尺寸；原片或内嵌预览不足 1024 时不凭空放大补充细节。专用缓存使用 JPEG 质量 90；保留修复后的睁闭眼判据和质量门参数。
- 缩略图已经按 EXIF 方向转正；保存实际输入来源与尺寸，不将缓存像素描述为原片细节。
- 每张照片只进行一次 SCRFD 检脸，不再执行全图加多分块重复检测。
- 每张脸分别定位两只眼，从缓存缩略图旋转裁剪到分类器输入。小脸、眼部像素不足、越界裁剪、明显侧脸、定位异常或无有效纹理返回不确定。墨镜、头发等遮挡尚未具备经过验证的独立识别器，不宣称质量门能识别所有遮挡。
- 睁闭眼候选 `open-closed-eye-0001` 使用两种上下文裁剪，与 EAR 交叉复核。保存每眼状态和原始候选分；通过像素／定位／姿态质量门且 EAR 明显高于模糊带（至少 0.22，同时高于配置模糊上界 0.02）时，按几何结果显示睁眼并跳过不必要的闭眼候选推理，不让未经 RGB 校准的候选否决明显张开的眼睑；边界状态与模型冲突或裁剪不一致时提示复核。复核说明区分睁闭眼状态与清晰度，不再统一提示模型未验证。模型与 EAR 都认为双眼闭合时，照片级只给“可能闭眼”复核提示，不升级成经过校准的确定闭眼判定。
- 质量门使用真实脸部最短边 48 像素、眼间距 18 像素、单眼宽 12 像素；不足仍返回不确定。小背景脸不会覆盖已识别为双眼睁开的主体，照片级显示部分人物可判断。
- 单眼闭合单独保留，默认不作为问题；设置中可开启“单眼闭合也提醒”。
- 清晰度使用局部拉普拉斯和 Sobel 边缘／纹理建议，优先足够大的人脸区域，没有有效脸部纹理时评估 3×3 区域中纹理充分的三个细节区域。给出清晰、偏软或需复核提示，不再因缺少已验证主体模型而一律无法判断。低纹理、纯渐变、小背景脸不直接判失焦。此结果明确标为选片参考，`calibrated=false`；它不是经过标注集校准的失焦概率，也不保证背景细节清晰等于主体对焦正确。
- 详情和选片窗口显示输入来源及区域说明；预览里点击区域说明可在图上定位，再次点击取消定位。未经校准的原始分不显示为准确率百分比。
- AI 预选和“连拍留最锐”不使用候选记录与诊断分。分析本身不会修改星级、用户决定、照片或 XMP。

## 资源、存储与任务

设置和任务抽屉现在统一显示“图片索引”（缩略图、详细信息、选片分析）。在设置 → AI → 图片索引中点击“重建”，四个内部通道会一起重排；语义与人脸仍独立管理。进度按照片计数，全部组成任务完成才算一张完成，缺失模型会明确显示等待下载。设置与任务抽屉同时展示各子项计数，避免部分分析已完成却只看到整体零完成。进度查询合并为单个在途请求，高频事件只追加一次后续刷新；已经返回的有效快照不会因新事件全部失效，切库后旧响应被隔离。图片索引支持统一启动、暂停与继续；重建与在途任务通过库级屏障隔离，避免旧结果回写。

闭眼模型增加到现有全局共享下载包，原有模型无需重下。分类器约 46 KB，SHA256：

`4daa100034482525a26c9afb9297c16580a531189e66e3d2b2ac7d32becfd593`

设置中的选片包同时检查当前档位 SCRFD 依赖；删除选片包保留共用检测器。建库开启全部 AI 时按现有进度页面准备这些资源。

原始 ONNX 输入为 BGR `(pixel - 127) / 255`、NCHW 32×32，输出 `19` 为 `[open, closed]` softmax。不能把 OpenVINO IR 的均值处理重复套到原始 ONNX 上。来源和预处理见 [官方清单](https://github.com/openvinotoolkit/open_model_zoo/blob/master/models/public/open-closed-eye-0001/model.yml) 和 [官方说明](https://github.com/openvinotoolkit/open_model_zoo/blob/master/models/public/open-closed-eye-0001/README.md)。训练扩展许可为 [Apache-2.0](https://github.com/opencv/openvino_training_extensions/blob/develop/LICENSE)；IR 数据集的公开成绩不能代替 RGB 摄影验证。

图片、语义、人脸各自的并发上限为物理 CPU 核心数的一半（至少 1），并遵守更低的进程可用 CPU 限制。三类互不共用限流名额；图片内部的缩略图/详细信息/选片分析共享图片额度。额度覆盖任务认领到落库，人脸结果等待聚类落库和语义批推理都计入上限。原始 GPU 模型会话保持共享，不为每个线程复制模型。选择小图后，远处小脸、眼部细节不足更容易返回不确定；这是用户选择的速度/精度取舍。高分辨率源图与分块适配器只保留用于显式离线评估。

数据库迁移 27 增加 `details_json`，旧 eyes/blur 计算结果失效并重排任务。区域说明和汇总原子写入，参数指纹包含算法版本、画质档位和单眼策略。现有暂停、恢复和全局下载去重继续适用。

## 失焦候选评估

`selection_defocus.rs` 提供本地 ONNX 评估适配器，保存主体区域与主体框以外区域的独立原始输出；不会把背景区域输出作为主体失焦判断，也不会写入生产判定。

D-DFFNet 仓库目前没有查到明确的权重分发许可，因此不加入自动下载清单。开发者可以在获准使用的本地作者代码和权重上运行 `scripts/export-defocus-candidate.py`。导出时必须核实 checkpoint 正类含义，通过 `--positive-class focus|defocus` 明确转换，不能猜测输出极性。脚本核对 PyTorch/ONNX 输出一致性；依赖只用于开发评估，应用不引入 Python/PyTorch。

导出契约固定 RGB/ImageNet 标准化、320×320，包装后的 `blur_map` 是 sigmoid 失焦图 `[1,1,320,320]`。同名 JSON manifest 记录契约、模型版本和 SHA256。评估时放入全局模型目录，名称分别为 `defocus-candidate.onnx` 与 `defocus-candidate.json`。未取得实际 D-DFFNet 权重，尚未执行该模型的真实导出、性能或跨平台验证。TOPIQ/MUSIQ 仍是待比较候选，没有把其技术质量分当作对焦概率。

## 后续摄影样本验证

不需要先训练新模型。准备几百张有明确人工标签的真实照片，再运行同批输入的比较：

1. 设置 `SMARTPHOTO_SELECTION_PHOTOS`（照片目录）、`SMARTPHOTO_SELECTION_MODELS`（已下载模型目录）、`SMARTPHOTO_SELECTION_OUTPUT`（新的 JSONL 文件）。
2. 运行 `cargo test --manifest-path src-tauri/Cargo.toml --test ai_selection_test export_selection_candidate_samples -- --ignored --nocapture`。只读取目录直属照片并写新的评估文件，不修改照片或应用数据库。当前目录导出支持闭眼新旧比较；失焦旧值为全图诊断基线，不能冒充完整旧版有人脸的最小值聚合。新失焦输出保持不确定，真实地图以 `defocusEvidence` 保存。
3. 标签 CSV 列为 `path,channel,expected,group,split`。eyes 标签 `open/closed`，blur 标签 `sharp/soft`；同一人物/连拍组使用同一 group，同组不能跨 train/val/test。
4. 运行 `python scripts/evaluate-selection-results.py --labels labels.csv --results results.jsonl`，分别报告误报、漏报、未判定、缺失结果和仅已判定样本的准确率。没有判定的候选不伪造准确率。

未知/疑似是复核与弃权状态；应与误报、漏报一起衡量，不能通过全部返回不确定来声称准确率提高。新模型正式成为生产判定前，仍需明确可接受误报/漏报、验证 RGB 场景、校准参数，并测量各平台性能。
