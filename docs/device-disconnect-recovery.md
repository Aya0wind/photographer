# 设备断连与恢复

适用于普通导入和联机拍摄。规则是：保留已完成照片，丢弃未完成传输，恢复其余工作。原始相机卡文件不因“丢失”记录而删除。

## 普通导入

- 每个文件读取前先将 journal 从 `pending` 改为 `copying`。断连或重启时，未完成的 `copying` 文件记为失败，错误以 `文件丢失，不再恢复：` 开头；残留 `.part` 清理，不参与恢复和“重试失败文件”。
- 已验证入库的文件保留；尚未开始的文件可在重连后通过任务抽屉恢复。重启会将运行中的导入变为暂停，历史任务提供恢复、取消入口。
- 支持设备、所选文件夹和多个文件/文件夹来源的断连识别，包含 Windows `E:` 形式的盘符。
- 新任务持久保存源相对路径及大小。恢复时先核对原对象 ID；ID 改变时，仅接受路径与大小唯一匹配。找不到、重复匹配或 ID 冲突的条目明确记丢失，不再静默少算。
- 多文件选择的根路径随任务保存，重启后可重建。旧版本任务没有这些记录时，需要重新选择来源。
- 设备 ID / 挂载根改变时，不会凭相同相机型号猜测设备身份；需要重新选择正确来源。

## 联机拍摄

- 窗口断连提示提供“重新连接”，继续使用原相册。不会自动重发快门。
- SDK / gphoto 完整下载在暂存文件旁保存 `.photographer-receipt.json`，记录文件名、对象 ID 和完整长度。重连后可以从旧会话目录补收入库，打开和清理仍受暂存路径校验约束。
- 完整本地下载的收据 ID 与照片登记在同一数据库事务提交，避免已入库但确认前崩溃后重复入库。
- 下载完整但入库失败的本地收据保留，允许补收。已开始而中断的远端传输、缺失对象及长度不完整的文件记为 `lost`，不再阻塞后续会话或固定后端。
- SDK 在报告断开前先排空已完成的下载队列。gphoto 的暂存写失败会关闭句柄并清理半文件；普通导入也会先关闭句柄再清理，兼容 Windows 文件锁。
- 旧版本留下的暂存文件没有完整下载收据，无法安全判定是否完整，保留供手动导入，不自动补收。
- 从未交付给应用、只存在于相机内存里的照片，以及未落入接收账本的对象，不能保证断电或重启后自动补收。相机卡上的原件仍可通过普通导入接收。
