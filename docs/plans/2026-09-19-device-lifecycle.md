# 设备连接管理

## 当前结构

- `devices/lifecycle.rs`：不执行 I/O 的连接状态机，由一个管理线程独占。设备不存在、接口存在但等待就绪、可访问是不同状态；扫描状态仍放在注册表内。
- `ipc/device_manager.rs`：启动枚举、系统通知、定时枚举和探测结果都在这里汇合。卷枚举、MTP 枚举和每台相机的探测分别异步执行。
- `ipc/reconcile.rs`：把管理器确认可访问的设备同步到注册表，并启动或重试扫描。前端继续读取注册表快照、接收文件增量。

删除了单独的健康监控线程与全局离线名单。WPD 继续使用现有的每设备串行工作队列，探测遇到扫描或传输忙时跳过。此次没有增加驱动卡死的进程隔离。

## 状态转换与时序

1. 先订阅通知，再启动系统消息窗口；立即枚举，之后每轮完成两秒后再枚举。通知提前触发下一轮。
2. MTP 接口出现后先探测可访问性；成功才注册并扫描。首次失败按 1、2、4、8 秒上限退避。
3. 在线设备每三秒探测，连续两次失败后摘除可用设备；接口仍在则继续退避探测，恢复成功后建立新扫描源。
4. 拔线通知立即移除旧连接。每次重新发现使用新的连接代次，旧探测结果直接丢弃。跨越系统通知的枚举结果也丢弃并重取。
5. 枚举失败代表未知，不代表所有设备已拔出。正常枚举为空才删除对应设备类别。
6. 注册表中的源 Arc 用来拒绝重连前的扫描结果和文件增量；同一源正在扫描时拒绝重复手动扫描。
7. 扫描失败保留可见错误，十秒后重试；扫描完成前持续发布文件增量。

## 验证

自动化覆盖 App/相机启动顺序、接口先出现但会话未就绪、无拔线通知的 MTP 开关、枚举失败、忙碌探测、两台相机独立恢复、100 次插拔的迟到结果、旧扫描失效，以及扫描完成前显示文件。

真机仍需回归：App 与相机分别先启动；同一根 USB 线上反复开启/关闭 MTP；扫描途中拔插；连续快速拔插；多台设备分别插拔。每次应确认设备列表最终一致，文件持续出现，扫描失败能退出“扫描中”并重试。

日志在应用配置目录 `logs/devices-*.log`，连接就绪、移除、枚举失败和扫描过程均有记录。
