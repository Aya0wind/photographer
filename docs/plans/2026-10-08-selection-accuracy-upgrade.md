# 清晰度与闭眼判定升级方案

日期：2026-10-08。

状态：已接入首阶段工程与候选评估通道，详见 [实现与验证边界](../selection-accuracy-implementation.md)。尚未完成真实摄影样本准确率校准、失焦候选权重实测、性能或设备验证；不宣称正式模型替换已完成。下文保留原方案及其制定时的源码基线。

## 1. 目标与原则

用户反馈当前清晰度和闭眼判定准确性不足，可以接受更大的计算开销。升级重点是高分辨率输入、主体局部分析和专用判定模型，并用实际摄影样本验证效果。

- 优先降低误报：正常背景虚化、笑眯眼、侧脸和遮挡不能直接成为淘汰照片的理由。
- 清晰度关注拍摄主体和对焦部位，分别展示主体清晰度与背景虚化情况。
- 闭眼分别分析每个人、每只眼睛，保留单眼闭合、遮挡和不确定状态。
- AI 结果仍是选片建议，不自动删除照片，不自动修改星级或写入 XMP。
- 增加计算开销不等于保证准确率提升；模型、阈值和结果融合规则都需要摄影样本校准。

## 2. 当前实现与主要限制

### 2.1 清晰度

当前实现位于 `src-tauri/src/ai/selection.rs` 的 `process_blur_task`：

1. 读取 512 档缓存缩略图。
2. 计算全图灰度拉普拉斯方差，并通过饱和曲线转换为 0–100 分数。
3. 如果数据库已有脸框，再计算人脸区域分数。
4. 取全图和所有人脸区域中的最低分，与软阈值比较，输出 `soft`、`sharp` 或 `unknown`。

限制：缩小后的图像可能丢失原片失焦细节；分数受纹理、噪声、对比度及缩放影响；背景虚化、低纹理区域、远处小脸可能拉低最低分。当前分数是启发式指标，不是经过校准的失焦概率。

### 2.2 闭眼

当前实现使用 SCRFD 检脸、FaceMesh 眼睑关键点和 EAR（眼部长宽比）阈值：

1. `face::detection_source` 优先使用已缓存的 512 档，再查 2048 档；没有缓存时生成 512 档。
2. 每张脸旋转对齐并裁剪到 256×256，推理眼睑关键点。
3. 双眼取较低的 EAR，各人脸再按最差结果聚合。
4. 输出闭眼、疑似或不确定；全睁或无人脸时不产生闭眼记录。

限制：固定 EAR 阈值对个体眼形、笑眯眼、侧脸、眼镜和遮挡不够稳健；小脸放大不能恢复眼部细节。当前导出模型的虹膜和 score 输出不作为有效判据，不能直接依赖它们改进置信判断。

### 2.3 现有精准档

现有精准档没有升级清晰度和闭眼通道。人脸检测输入仍固定为 640×640；只把源图换成更大的图片，并不会自动提高小脸检测所用的输入分辨率。新方案需要单独升级取图、检测和局部裁剪策略。

## 3. 总体处理流程

```text
高分辨率取图与方向校正
  → 全图检测 + 必要时分块检测
  → 主体、人脸和眼部定位
  → 从高分辨率源图提取局部区域
  → 专用清晰度模型 / 睁闭眼分类模型
  → 图像质量、姿态和遮挡检查
  → 对疑难结果进行第二模型或多尺度复核
  → 按区域保存结果、置信度与不确定原因
  → 汇总为可解释的选片建议
```

### 3.1 输入与局部裁剪

- JPEG 等格式优先从原图或足够大的解码图取局部，避免先缩成 512 再放大。
- RAW 优先使用足够大的嵌入预览；细节不足时允许完整解码。记录实际使用的是嵌入 JPEG 还是 RAW 解码结果，避免把两者当作完全一致的证据。
- 首版可以评估长边 2048/4096 的检测源，但这只是候选配置，需比较准确率与解码成本。
- 小脸检测采用分块或多尺度检测，再将检测坐标映射回源图裁剪。维持现有归一化脸框坐标契约，并统一 EXIF 方向和旋转处理。
- 对不足以判断的眼部像素标记“不确定”。不使用超分辨率、去模糊或额外锐化生成的细节判断原片是否清晰。

## 4. 清晰度升级

### 4.1 从全图最低分改为主体局部判定

人像重点分析人脸和眼部；多人照片保存每张脸的结果，不让一个远处小脸直接决定整张照片不清晰。

非人像照片需要识别主体区域。没有可靠主体时，可以保留整体技术质量分，但不能把正常浅景深或背景失焦直接判为主体失焦。

建议至少区分：

- 主体清晰、主体疑似失焦、主体明显失焦。
- 背景虚化或局部失焦区域。
- 因主体不明、像素不足、低纹理或来源不可用而无法判断。

### 4.2 候选模型

| 候选 | 用途 | 使用边界 |
| --- | --- | --- |
| D-DFFNet | 输出局部失焦区域，结合主体区域汇总 | 重点针对离焦模糊；需要另行验证运动模糊、人脸和眼部效果 |
| TOPIQ 的无参考模型 | 辅助评价整体技术质量 | 综合质量分不能直接等同于对焦准确率；局部裁剪输入也需要验证 |
| MUSIQ | 多尺度图像技术质量评价，作为辅助或复核候选 | 同样不能直接替代主体对焦判定 |
| 摄影样本微调的局部清晰度分类器 | 直接分类主体、脸部或眼部的清晰程度 | 需要符合实际使用场景的标注数据、独立验证集和可分发权重 |

推荐先评估“局部失焦模型 + 主体区域”的组合，整体质量模型作为辅助信号。拉普拉斯或其他传统指标可以保留为调试信息，不再独立承担最终判定。

## 5. 闭眼升级

### 5.1 专用分类器与质量检查

保留人脸检测、对齐和眼部定位能力，将 EAR 从主要决策依据降为辅助信息。从高分辨率图分别提取左右眼，并在必要时结合整脸或上半脸的上下文。

每只眼睛先检查有效像素、定位质量、姿态和遮挡，再输出睁眼、闭眼、疑似或不确定。眼镜反光、墨镜、头发遮挡、明显侧脸和定位失败，不应被硬判为闭眼。

脸级结果区分双眼闭合、单眼闭合以及疑似眯眼；照片级记录具体哪张脸存在问题。是否将单眼闭合视为选片问题需要独立配置，避免把有意眨眼等拍摄效果一概归为失败照片。

### 5.2 候选与进阶路线

- Intel `open-closed-eye-0001` 是现成的专用睁闭眼分类器，可以作为第一轮对照候选。
- 该模型使用 MRL Eye 数据训练和验证，而 MRL 是红外眼部数据；其公开准确率不能直接代表普通摄影照片的效果，也不能据此保证优于当前实现。
- 如果现成模型不能满足实际误报率要求，采用 ResNet 或 ConvNeXt 等分类骨干，使用实际摄影样本微调；覆盖笑眯眼、侧脸、眼镜、遮挡、小脸、低光和不同眼形。
- 多模型或多裁剪尺度复核只用于质量合格但结论不稳定的样本；缺少有效像素时直接“不确定”，避免重复推理产生虚假的确定性。

这是静态照片眼部状态判定，不把必须依赖视频时序的眨眼检测模型直接用于单张照片。

## 6. 结果与界面

建议保存区域级结果，而不是只保留整张照片的单一最差分：

- 主体框、人脸框、眼部框和使用的源图分辨率。
- 模型原始分数、判定类别、经过校准的置信信息。
- 不确定原因，例如“小脸”“眼部遮挡”“主体未确定”或“原文件不可用”。
- 模型版本、预处理版本和判定参数版本。

选片界面可定位具体人脸或主体，并分别展示“主体疑似失焦”“背景虚化”“第 2 人闭眼”等提示。未经校准的模型输出或启发式分数，不作为准确率百分比展示。

## 7. 接入与计算成本

- 沿用 Rust 后端、模型下载管理、索引任务和现有 GPU 优先 / CPU 回退机制。
- 候选模型的 ONNX 导出、动态尺寸、算子支持、预处理及各平台执行后端，需要逐个验证，不能默认已有 PyTorch 权重即可直接接入。
- 高分辨率解码尽量在一次任务内复用；人脸和眼部局部推理评估批处理，避免为每只眼睛重复解码整张照片。
- 限制并发、缓存数量和在途图像内存；大量 RAW 的解码成本可能超过模型推理成本。
- 疑难样本复核和完整 RAW 解码可以作为高精度分析步骤，已有浏览缩略图继续服务界面，不阻塞照片浏览。
- 调整 `FaceEyeStateClassifier` 的结果契约以承载分类结果、左右眼和不确定原因，不再要求新分类器返回 EAR 数值。
- 更新算法指纹和模型版本，明确旧结果重建策略。沿用现有暂停、恢复和来源失效处理，不把分析失败当作“清晰”或“睁眼”。
- 在选择可随应用分发的模型前核对代码、权重和训练数据的具体许可。源码开放不等于所有权重和数据都可自由分发。

目前没有本项目的新方案耗时或显存实测，不承诺固定的单张耗时和资源占用。

## 8. 实施顺序

1. **输入与结果结构**：升级高分辨率取图、分块检测和局部裁剪；增加区域结果及不确定原因，复核现有预处理与输出解析。
2. **闭眼候选对比**：引入专用分类器，与 EAR 方案在同一组摄影样本上比较。
3. **清晰度候选对比**：评估局部失焦模型与主体区域组合；验证整体质量模型能提供的辅助价值。
4. **疑难样本与微调**：收集误判场景，评估多尺度复核、第二模型和专用分类器微调。
5. **工程接入**：完成模型下载、跨平台推理、版本重建、缓存与任务调度，以及可解释的选片界面。

## 9. 准确率验证要求

正式切换判定方案前，需要人工标注的真实摄影验证集。首轮可从几百张照片开始，并持续补充误判样本。

- 覆盖主体清晰但背景虚化、整图失焦、运动模糊、低纹理、高 ISO、多人大合照及小脸等清晰度场景。
- 覆盖正常睁眼、闭眼、眯眼、单眼闭合、侧脸、眼镜、遮挡和低光等眼部场景。
- 同一人物和同一连拍组尽量放在同一数据划分中，避免高度相似样本同时进入训练与验证集。
- 在相同样本上比较当前方案和候选方案，分别报告误报、漏报和不确定比例；不只报告总准确率。
- 单独评估背景虚化误报、小脸误报和多人照片聚合误报。
- 先约定可接受的误报率和漏报率，再决定阈值及是否替换模型。

是否开展这些模型实验、性能测量和真实设备验证，需要在实施阶段明确；本文没有执行任何此类验证。
