# 服务端协作、客户端接入与同步计划

返回 [方案入口](README.md)。本地桌面/手机单用户模式、远程协作模式和浏览器异步模式共享数据语义，但拥有不同的执行与生命周期。

## 1. 服务与客户端分工

| 位置 | 负责 | 不能依赖的假设 |
| --- | --- | --- |
| Linux server | 用户/成员/工作区、资源授权、共享版本、任务、同步真值 | 桌面窗口、联机拍摄、进程全局活动数据库、GPU 必定存在 |
| 浏览器 frontend | 照片管理/协作、配方提交、异步预览/导出、下载 | Tauri API、服务器本地路径、实时图像处理引擎 |
| 桌面/手机远程客户端 | 登录连接、资源缓存、本机编辑、同步 journal、冲突展示 | 本地整数 ID 等于服务器 ID、登录自动接管本地库 |
| 桌面/手机本地模式 | 本地图库/配方/处理与输出 | 网络、登录、服务端角色 |

共享 model/media 不接收用户角色做图像计算。服务端先鉴权、固定来源与配方版本，再提交工作；客户端携带的 workspace 只是选择器，不是授权证明。

## 2. 资源与设置作用域

区分服务器级设置、共享工作区设置和个人偏好。本地 active_database 仍是本地宿主的选择，不进入服务端请求路由。服务端每次操作有明确用户/工作区范围。

资源包括原图、缩略图、代理、LUT、编辑版本、导出结果和 AI 索引。原图/代理下载与任务事件遵守同一权限范围，文件哈希相同或 ID 难猜不能替代授权。服务端 URI/存储键不作为本地绝对路径返回浏览器。

本地连接按 server/workspace/resource 保存映射，允许两个服务器出现同名或同值资源 ID；退出远程连接不删除独立本地照片。凭据由宿主安全存储适配管理，不写入可共享配方。

## 3. 首期协作方式

- 共享图库/相册与每张原图的多个编辑版本；个人草稿和共享发布分开。
- 保存带基础 revision，事务内比较并更新；冲突保留本地草稿并明确返回，不静默覆盖别人版本。
- 预览参数是临时会话状态，不为每一帧写一份共享版本；保存/发布时才形成持久 revision。
- 角色/操作能力作为服务合同，具体权限表在 M6/M7 细化。多人同时修改同一曲线/蒙版的实时合并不在首期，后续需要独立操作模型。
- 评分/标签/评论和人脸命名需明确个人还是共享作用域，避免新增协作后混用已有本地字段。

M6 首次开放共享写入即具备授权和 revision 前置检查；M7 完成成员/版本工作流、冲突呈现和客户端同步，不把并发正确性留到第二版保存接口再修补。

## 4. 同步内容与流程

优先同步元数据、相册关系、编辑版本/配方、LUT 引用和结果资源。原图选择性上传下载，缩略图/高精度代理按需获取；GPU 缓存、视口、运行时句柄、绝对路径和模型文件不默认同步。

```text
首次连接：认证/能力检查 → 授权工作区快照 → 本地资源映射 → 增量游标
本机修改：保存本地草稿与待提交操作 → 上传所需资源 → 幂等提交 → 确认 revision
重连同步：校验权限 → 拉变更/删除标记 → 推待提交操作 → 处理冲突 → 推进游标
```

流程原则：

- operation_id/幂等键解决重试，内容版本和 hash 解决资源完整性，revision 解决并发；不使用本机时钟决定谁覆盖谁。
- 变更游标与提交回执持久化；游标过期重新快照/对账，不能丢掉未提交操作。
- 上传临时对象完成校验后登记；配方依赖的 LUT/来源版本齐备后才接受相应共享版本。
- 删除共享记录、删除本地缓存、删除受管理副本、删除独立本地原图分别处理；首期不把服务端 tombstone 自动转成永久删除本地原图。
- 原图只在远程且未下载时，离线只能查看已有内容；不能声称“支持离线”就代表所有原片可编辑。
- 手机挂起后可暂停传输，恢复按 journal/游标续做；同一同步状态机配不同资源预算，不依赖移动后台永久运行。
- 撤权后停止继续拉取/提交/事件访问；已下载字节不能靠服务器撤权远程抹除，缓存处置按客户端策略执行，不承诺不可实现的撤回。

## 5. 异步编辑、导出与持久任务

浏览器提交固定来源/配方的任务并得到任务标识，显示进度，完成后读取授权 JPEG/PNG 预览或成片资源。旧请求结果不覆盖新配方；不传逐帧 float 缓冲，也不建设浏览器 LibRaw/GPU 引擎。

服务端持久任务记录来源版本、配方/资源版本、用户/工作区、幂等键、阶段与结果回执。worker 用租约领取，崩溃后恢复；状态提交与资源登记要可重试，避免重复照片。浏览器关闭后持久导出继续，临时预览按 TTL 清理。

全局资源预算之外增加用户/工作区公平预算。原生解码崩溃与 OOM 不能靠线程 panic 捕获完全隔离，独立 worker 进程在实测后评估；不提前要求微服务与外部消息中间件。

## 6. 数据库与版本兼容

本地继续现有 SQLite。服务单节点原型可用 SQLite 证明业务，持续高写入或多实例时评估 PostgreSQL；具体选型在原型/负载后由用户决定。

远程协议版本与配方版本分开。服务返回实际支持的渲染/资源能力；客户端可保留未知字段，但不能在无法正确解释时提交“规范化”后的残缺配方。只有全部所需阶段可执行时才渲染，否则返回明确不支持。

已有本地未发布 schema 不增加通用历史迁移框架；持久部署的服务在首次正式发布前另定升级、备份和恢复合同。不能把 `CREATE TABLE IF NOT EXISTS` 当服务升级策略。

## 7. 阶段交付

| 阶段 | 最小闭环 | 关键失败场景 |
| --- | --- | --- |
| M6 | 上传、管理、配方保存、异步预览/导出、授权下载 | 非法范围、资源缺失、worker 重启、浏览器断线 |
| M7 | 两用户协作、桌面远程连接、离线 journal、增量同步 | 并发 revision、重复上传/提交、游标失效、撤权、删除与冲突 |
| M8 | 手机复用同步并接原生文件/生命周期 | 进程终止、后台中断、权限变化、缓存淘汰后恢复 |

验收不要求 Web 实时帧率，但要求任务反馈、结果正确、资源隔离和恢复可靠。完整场景见 [验证矩阵](validation.md)。
