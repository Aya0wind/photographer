# 模块移植与兼容实现思路

返回 [方案入口](README.md)。阶段编号见 [实施顺序](implementation.md)。以下给出代码归属和迁移方法，不锁定接口签名。

## 1. 迁移原则

先保留现有算法、参数和持久化含义，提取调用边界；之后再引入 LibRaw、资源来源和服务端协作行为。不会以重新分模块为由重写 PhotoCraft、SQL 或已经工作的导入校验。

“可复用”分为三类：原实现迁入、保留实现但换输入/宿主适配、必须新增。表中只有后者表示新开发，不把改 import 路径称为完成手机/服务器移植。

## 2. model：稳定数据和配方

**来源：** `src-tauri/src/edit/recipe.rs`、`events/mod.rs` 的领域枚举、`db/mod.rs` 的部分资产描述、前端配方类型。**阶段：M2。**

- 迁入纯配方、坐标、参数边界和结构校验；数据库行、内部事件和网络 DTO 不全部塞进 model。
- `ColorGrading` 当前引用 PhotoCraft Wheel，Development 默认值也取自上游；替换为项目类型和受版本约束的默认值，在 media 转换到上游类型。
- LUT ID 的结构校验可在模型层，资源是否存在/是否有权限由应用与资源服务检查；不让模型访问全局 LUT 目录。
- 格式版本、渲染版本、资源版本与并发 revision 分离。未知配方字段的透传/编辑规则以样本验证，不在 normalize 时默默删掉。

**兼容出口：** 现有 JSON 样本解析、默认值、夹取边界和序列化语义一致，代表照片效果不变。只更新结构类型不自动变更用户保存的 renderer。

## 3. media：图像处理与现有编辑链

**来源：** `edit/photocraft.rs`、`source.rs`、`preview_renderer.rs`、`masks.rs`、`grading.rs`、`parametric.rs`、`meta.rs`、`tiff_metadata.rs`、`gpu.rs`。**阶段：M4，新增显影 M5。**

- 保留 PhotoCraft 的调色、调整层、蒙版、混合、LUT、ICC、几何和输出能力；外部依赖固定提交，适配集中在 media 内部。
- 拆开来源读取、解码/显影、参数到处理阶段、CPU/GPU 执行、结果编码。高层接受准备好的输入/访问结果，不能自行从 AppState 查路径。
- `native_presenter.rs` 的 HWND/窗口显示留在桌面 app；media 可提供 GPU 结果，但不拥有 OS 窗口生命周期。
- CPU 图像格式/色彩与 GPU 资源归属显式描述；读回、全图转换和分配次数进入性能诊断，分块过滤保留邻域与源坐标。
- M4 先沿用现有解码与渲染结果；M5 才接 LibRaw、线性代理和胶片合同。查看器的 rawler 路径单独盘点，确认替代完成前不因编辑器迁移直接删依赖。
- PhotoCraft 原生文档、16 位导出、透明度、文字/字体和通道布局分别验收，不能只看 JPEG 成功。

**兼容出口：** 同一冻结配方在旧路径与新 media 路径有对应图像/元数据证据；GPU/CPU 误差有定义，源文件字节不变。

### 导出与目标提交

`edit/export.rs` 中冻结配方、处理/编码、目标落位与成片登记逐步分离。media 负责生成结果；app 的目标适配负责本地目录、受管理图库、系统相册或服务资源，返回目标身份与提交回执，不要求绝对路径。

M3/M4 先保持现有本地临时文件/rename 和数据库登记行为，并用假目标验证写入、提交、失败中止。M6/M8 再接服务/手机目标各自的提交规则。目标提交成功而登记失败时保留回执，恢复先对账，避免重试重复生成照片；没有来源写权限时不能强行写 sidecar 或修改系统原图。具体接口签名在实现时确定。

## 4. catalog：业务规则与显式数据作用域

**来源：** `db/assets.rs`、`albums.rs`、`groups.rs`、`libraries.rs`、`editor.rs` 相关业务，`ipc/assets.rs`、`albums.rs`、`library.rs`、`edit/project.rs` 内的组织逻辑。**阶段：M3。**

- 从“IPC 自己开当前数据库并做业务”变为 app 选择作用域、catalog 执行业务、存储提供事务能力；本地无需 Actor/Workspace 权限上下文。
- 保留相册/分组/评分/版本关联与资产归属校验；分清业务对象与数据库行。
- 业务所需的仓储操作包含必要事务语义，避免一个多步原子操作拆成若干无事务 getter/setter。
- 服务器在外层执行成员与资源授权，再调用适用的共用逻辑；不能将桌面全局 active_database 直接复用于服务器。

**兼容出口：** 多本地数据库切换不串资产、相册关系与导出登记不变；用户授权仍是服务端职责。

## 5. storage-sqlite：现有 SQL 与本地持久化

**来源：** `src-tauri/src/db/` 的 SQL/schema、`settings` 的本地存储组织、编辑配方/导出日志相关实现。**阶段：M3。**

- 复用现有查询、WAL/锁等待和事务处理，改为明确打开具体库；禁止共享库把“当前数据库目录”当进程全局真值。
- 持久数据、受管理原图与可删除缓存分离；路径解析留在存储/来源适配，业务持有稳定身份。
- 遵守当前未发布单版本 schema 约定，不在目录重构中新增历史 migration 框架。修改 schema 前说明现存开发数据怎样处理；不会默认删除或重建用户库。
- 本地配方普通保存保留现有语义。服务协作的 expected_revision 比较和更新需在同一事务内实现，不能复用普通 upsert 冒充并发保护。
- 服务可先用 SQLite 适配验证流程，PostgreSQL 仅为后续候选；不抽象成能执行任意 SQL 的万能 repository。

**兼容出口：** 本地资产数量、相册关系、配方、任务日志和配置目录保持；并发及失败事务不产生半登记结果。

## 6. runtime：多核、资源与可取消执行

**来源：** `tasks/mod.rs`、`tasks/index_budget.rs`、`thumbs` 的许可池、GPU/模型缓存生命周期。**阶段：M3，持续性能工作 M4/M5/M8。**

- 提取取消、进度、任务完成信号和资源许可；TaskSupervisor 的业务标签/事件映射留给 app。
- 把 RAW、缩略图、AI、导出的并发与内存放进同一宿主预算，复用现有 permit 思路；不能再各自按核心数创建满载池。
- Rust 并行与 C/C++ 库线程避免嵌套超额；GPU 提交和 CPU 回退也计入预算，失败执行未结束前不释放许可。
- 通用缓存负责租约/淘汰机制，缓存键与具体失效条件由 media/来源等能力定义。
- 进程内执行器不承担全部持久任务真值：导入日志、服务任务与同步 journal 由对应业务保存，恢复后重新派发。

**兼容出口：** 现有暂停/取消/失败上报不丢失；无死锁、无许可泄漏，用户前台操作不被后台重任务长期挤占。

## 7. protocol 与 sync：复用契约，新增远程流程

**来源：** `src/ipc/api/types.ts`、Rust DTO、事件载荷；现有 import 日志/校验提供机制参考。**阶段：M2 契约整理，M6/M7 实际远程实现。**

protocol 保留业务含义，补作用域、版本、结构化错误和资源描述，不公开任意 invoke 命令。内部事件与授权外发事件分开，协议不携带服务器绝对路径。

sync 的网络资源映射、游标、操作日志和冲突状态主要是新增。复用内容校验、幂等思路和本地持久化组件，但不把导入 move/delete 语义带到双向同步。桌面/手机共享状态机，原生密钥保存、联网/后台和文件访问通过宿主接入。

**兼容出口：** 本地模式不要求登录；远程会话不改变本地库归属；旧客户端未支持的配方字段不会因一次保存丢失。详细场景见 [同步专项](collaboration-sync.md)。

## 8. ai、metadata、geo

| 能力与当前来源 | 复用方式 | 兼容与性能验证 |
| --- | --- | --- |
| ai：`ai/embed.rs`、`face.rs`、`selection*`、`focus_quality.rs` | 推理与后处理迁入 ai；模型目录、图像读取、索引任务与 app 编排分开，ai 接收图像视图 | 同模型/前处理的结果对照；EP 不支持时 CPU 回退；移动库、模型内存与启动成本实际验证 |
| 语义/人脸索引：`ai/semantic.rs` 等 | 算法/索引实现保留，数据库关系归 catalog/存储，索引作用域由 app 明确传入 | 保留已有向量与 SQLite 记账约定；服务按工作区隔离，不能跨用户检索；目录迁移不触发无理由全库重算 |
| metadata：`metadata/exif_lite.rs`、`xmp.rs`、`phash.rs`、`edit/meta.rs` 中通用部分 | 提取纯解析/编码与计算；媒体封装相关代码按依赖留 media，文件写回由 app/存储负责 | EXIF/ICC/方向/GPS/未知 XMP 字段保留规则不变；无写权限时只存应用元数据或写导出物 |
| geo：`geo/` | 地理算法和离线数据格式保留；安装、目录和 UI 资源 URL 分离 | 缓存版本、数据缺失与更新可恢复；服务资源端点不返回本地 asset URL |

AI、geo 能力按实际产品需要启用；尚未确定的功能裁剪不能成为共享 core 强依赖。

## 9. import、来源、缩略图与设备

**来源：** `import/engine`、`devices::DeviceSource`、`thumbs`、`edit/proxy_cache.rs`。**阶段：M3/M4。**

- 保留复制、内容校验、查重、任务日志和原子落位；设备发现/枚举在宿主，来源读取不要求每种资源都能删除或列全设备。
- DeviceSource 的流和缩略资源可以由适配复用，不直接把它当长期图库资产身份；权限租约、内容版本、云端下载与可寻址文件准备另设边界。
- 缩略图生成属于处理能力，队列/预算使用 runtime，索引登记由 app/catalog 编排；代理缓存跟随数据类型分开，JPEG 缓存不能冒充线性代理。
- 先本地文件与无路径假源，再手机 URI/系统照片与远程资源；只有库要求且来源不满足时才物化临时文件。
- Windows WPD、联拍、桌面热插拔继续留桌面 app。服务器不启动它们；手机系统照片 API 不伪装为 Windows 设备实现。

**兼容出口：** 复制校验、暂停恢复、同卷快路径及不支持操作的含义明确；缓存变化不会误删源。原子替换原件等已有文件所有权规则逐项保留。

## 10. 前端、IPC 与产品宿主

| 现有位置 | 迁移目标与处理 |
| --- | --- |
| `src/features/editor/lib` 的 recipe/coords/geometry/history 纯逻辑 | components 下有实际消费者的包，公开入口消费源码；保留相关相邻单测 |
| `previewScheduler`、编辑器 store | 先隔离 Tauri/窗口与应用全局状态，再提取可复用状态机；Web 异步任务不强行复用本机帧调度 |
| `src/ipc/index.ts`、`api/events.ts` | Tauri 传输留本地适配，远程适配实现业务合同与重连；不在每个页面散布平台判断 |
| `src/stores` 和各产品页面 | 跟随 app；只有纯逻辑/确实共用的组件提取，不把所有 store 作为共享全局单例 |
| `src-tauri/src/lib.rs`、`AppState` | 桌面宿主与薄命令壳；逐步显式传服务/作用域；手机/服务有独立入口，不复制整个桌面启动函数 |
| `platform/`、原生画布、系统字体 | 各 app 的平台适配；能力返回区分不支持/暂时不可用/未授权，字体与色彩输出纳入对照 |

服务器异步编辑必须保留桌面/手机上传的完整可支持配方，即使浏览器未提供对应控件；未知版本无法可靠处理时返回不支持，保留原始内容。

## 11. 临时兼容与退出条件

| 兼容点 | 临时方法 | 退出条件 |
| --- | --- | --- |
| Rust 原模块路径 | 薄 re-export/委托到新 crate | 所有生产/测试消费者已迁入，依赖图无反向引用 |
| TypeScript 原 API 导入 | 旧入口转发到公开组件/适配 | 页面与测试迁完，无两套默认值和校验 |
| 原生接口/数据缓冲 | 显式转换与生命周期桥接 | 色彩、所有权、方向、错误与峰值内存验证通过后删冗余转换 |
| 旧渲染配方 | 固定渲染合同，必要时保留旧后端 | 有明确转换规则和用户决定前不自动重解释 |
| 路径型来源 | 本地来源适配包装现有实现 | 无路径纵向流程通过，消费者不再自行假定可读绝对路径 |
| 旧持久数据 | 保持当前本地读取语义 | 单独确定数据策略并验证后才变更；不与机械移动混做 |

回归不仅检查“能编译”：旧配方与资源 ID、像素、元数据、数据库关系、错误语义及热点复制/并发行为都需有对应证据。未验证的平台或样片明确列为待验。
