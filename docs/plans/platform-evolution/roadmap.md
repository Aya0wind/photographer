# Roadmap、决策节点与风险

返回 [方案入口](README.md)。

2026-10-14 开始 RawLab/LibRaw 的 M0 原型，详见 [实施记录](../2026-10-14-rawlab-port-progress.md)。这里只标记实际代码进展；真实样片/原生运行/性能出口未验收，M0 尚未完成。本文件统一维护实施状态；具体步骤见 [implementation](implementation.md)，验证方法见 [validation](validation.md)。

## 1. 当前状态与交付顺序

2026-10-14：M0 的 RawLab/LibRaw 原型已开始，其余阶段待开始。现有桌面功能是迁移输入，不表示共享处理、手机或服务已实现。早期盘点基线为 `177205a`，本批实施基线为合并提交 `fcf3257`。

| 阶段 | 优先顺序与依赖 | 可交付结果 | 完成条件 | 状态 |
| --- | --- | --- | --- | --- |
| M0 基线与原型 | 首先执行 | 桌面回归/性能基线、RAW 色彩/内存、无头与手机原生依赖原型 | 关键可行性有记录，阻塞点有处理结论 | 原型进行中，出口待验 |
| M1 工程组织 | M0 后 | 单仓多应用布局、根 workspace、独立构建入口 | 桌面新路径可构建并使用原有数据，未混入业务变更 | 待开始 |
| M2 纯合同与组件 | M1 后 | model、纯 TypeScript 组件、适配边界 | 不依赖 Tauri/PhotoCraft 的模型与组件可用，旧配方语义保持 | 待开始 |
| M3 来源/存储/runtime | M2 后 | 来源访问、catalog/SQLite 分离、共享预算 | 无路径来源纵向流程、明确数据作用域、并发限额生效 | 待开始 |
| M4 共享处理 | M3 后 | media 与本地应用服务，AI/metadata/geo 按需提取 | 桌面回归与无头 CPU 流程通过，无不可解释的性能退化 | 待开始 |
| M5 RAW 与胶片 | M4 后；原型从 M0 开始 | LibRaw、线性代理、胶片、完整 RAW 导出 | 最新配方切换、实时反馈、颜色和资源预算有实测证据 | 待开始 |
| M6 Linux/Web | M4 后；可与 M5 分别交付 | 服务器与 frontend 管理、授权、异步高级编辑 | 无 GUI/无 GPU 可完成上传到成片，作用域隔离与写入版本检查有效 | 待开始 |
| M7 协作/同步 | M6 后 | 多用户版本、桌面连接、共用 sync | 两用户冲突、离线重试、撤权和重启恢复通过 | 待开始 |
| M8 手机收口 | 本地依赖 M4，协作依赖 M7，新 RAW 依赖 M5 | mobile 的 Android/iOS 适配与独立发布 | 按确认的功能表完成真机验证，共享变更未破坏其他产品 | 待开始 |

M0–M8 是本轮架构演进编号，与早期产品计划中的同名里程碑无对应关系。RT0–RT5 是 [实时专项](realtime.md) 内的验收检查点，不是第二套实施顺序。

推荐先交付 M0–M4 的共享基础，再优先完成 M5 本地编辑目标。M6 可在共享基础稳定后独立推进，不等待胶片全部优化；此时只开放服务器实际支持的渲染能力。M8 的最小构建/系统照片/显示原型前置，完整产品的功能清单与发布顺序后续确认。

## 2. 可审查工作包

每个工作包以实际可运行的纵向流程为结束点，避免仅创建目录和 trait 就标记完成。单个阶段可拆多个提交，阶段状态以出口证据更新。

### M0–M1：先让结构调整可验证

- [ ] 记录现有样片、配方、数据库副本、原图 hash 与桌面基线；明确哪些目标平台尚无验证环境。
- [ ] 完成 Linux 无头 CPU、手机原生依赖/表面、LibRaw 色彩交接和峰值内存原型。
- [ ] 依据原型确定近期阻塞决策；将纯目录移动和依赖升级分开。
- [ ] 迁移 desktop，调整 workspace、构建/资源/安装/测试路径，核验旧配置与数据目录。

### M2–M4：逐项复用现有实现

- [ ] 提取 model 的纯配方与稳定默认值；隔离 PhotoCraft 类型转换。
- [ ] 按公开包入口提取 components 纯逻辑与原有测试，保留产品页面/宿主适配。
- [ ] 跑通无路径来源到编辑打开，分离 catalog 和 SQLite，替换全局活动库依赖。
- [ ] 统一处理预算、取消与进度；保留导入 journal 等持久恢复机制。
- [ ] 保持旧操作顺序提取 media，分开计算与原生呈现，完成桌面/无头对照。
- [ ] 按实际消费者提取 AI、metadata、geo、import；完成临时转发入口清理。

### M5：先正确，再完成实时目标

- [ ] LibRaw 到线性工作空间、CPU 胶片参考、配方渲染版本与资源版本可追溯。
- [ ] JPEG 编辑到线性代理切换不丢历史、不回滚参数，失败可继续当前编辑。
- [ ] 白平衡和空间滤镜分别确定可接受交互方案，验证完整 RAW 导出一致性。
- [ ] 按测量结果优化 GPU/多核/复制，验证 Auto、CPU、Force GPU 与低资源行为。

### M6–M7：先服务闭环，再协作恢复

- [ ] Linux CPU 服务与 frontend 跑通上传、管理、配方、异步预览/导出和授权下载。
- [ ] M6 的共享写入已有授权与事务 revision 前置检查，后续协作沿用该保存语义。
- [ ] 持久任务具备重启恢复、幂等登记与结果回执，公平预算可观察。
- [ ] 事务 revision、个人草稿/共享版本和资源作用域通过双用户验证。
- [ ] 桌面通过共用 sync 完成离线 journal、资源传输、增量拉取与冲突处理。
- [ ] 正式持久部署前确定数据库升级、备份/恢复与协议兼容策略。

### M8：在真机完成产品适配

- [ ] 按确认清单装配本地与远程模式，系统照片/授权不依赖普通路径假设。
- [ ] 完成表面重建、低内存/热状态、后台暂停与进程终止恢复验证。
- [ ] 同步复用 M7，平台差异仅通过宿主适配和预算体现。
- [ ] 各产品独立构建/发布，共享修改有受影响消费者的回归记录。

## 3. 待定事项与决策时机

以下尚未定案。实施者先准备最小原型、成本与限制，再由用户决定影响架构或产品范围的选项；不要求现在确定接口签名。

| 待定问题 | 最晚需要决定 | 需要的依据 |
| --- | --- | --- |
| 来源接口归属、是否独立 asset-io | M3 提取前 | 本地文件、无路径来源、临时文件租约和实际依赖图 |
| 前端包管理与 workspace 工具 | M1 构建调整前 | 现有锁文件/CI、源码组件消费、应用独立打包原型 |
| 手机 UI 宿主、GPU 计算/显示后端的复用方式 | M0 原型后，M8 正式接线前 | Android/iOS 编译、纹理交付、字体/颜色与生命周期证据 |
| LibRaw 构建、C ABI、第三方源码/补丁存放 | M0 原型后，M5 正式接入前 | 平台工具链、线程控制、分发许可和可复现构建；具体签名单独设计 |
| 代理格式/尺寸、白平衡交互、各设备 CPU/RAM/VRAM 预算 | M5 默认行为启用前 | 冷热延迟、切换色差、完整 RAW 峰值内存与样片覆盖 |
| HTTP 栈、持久任务实现、服务数据库、worker 是否独立进程 | M6 持久服务前 | 无头原型、并发/故障数据、部署复杂度与恢复要求 |
| 首期权限表、共享字段归属、冲突操作与原图同步策略 | M6/M7 对外使用前 | 两用户实际工作流、配额/资源成本与离线语义 |
| 浏览器和手机的具体功能裁剪 | 各产品功能实现前 | 已确认产品定位、共享引擎能力与设备限制 |
| 发布后的协议/数据库兼容期限和升级路径 | 首次持久部署/正式发布前 | 实际版本支持范围、备份恢复演练与回滚约束 |

扩展性通过版本、能力、可选项和明确边界预留；暂不创建插件 ABI、大量空 crate 或通用远程像素接口。若新决策改变已确认依赖方向，应先更新架构文档并说明影响。

## 4. 主要风险与处理

| 风险 | 暴露阶段 | 处理与交付限制 |
| --- | --- | --- |
| 原生依赖只能桌面运行，或无 GPU 无法渲染 | M0 | 前置最小构建/CPU 渲染，区分算法依赖和宿主功能；不能以桌面成功代替移植完成 |
| JPEG/RAW 切换、白平衡与旧配方颜色不一致 | M0/M5 | 固定色彩/渲染合同，保留旧语义，按样片和 CPU 参考对照；不承诺无条件无色差 |
| RAW/AI/导出并发使 RAM/VRAM 超预算 | M0/M3/M5/M8 | 计入中间缓冲和在途任务、统一预算、分块与按测量选择并行度 |
| 本地路径、全局活动库和 LUT 缓存污染服务作用域 | M3/M6 | 无路径来源流程、显式作用域、资源授权和缓存隔离测试 |
| 机械迁移混入 schema/算法变更导致无法回退 | M1–M5 | 拆提交，保留输入样本和数据副本；格式不兼容时另定恢复方案 |
| 离线重试覆盖他人版本或传播删除 | M7 | revision、幂等回执、journal、冲突保留；删除类别分别处理 |
| 抽象增加分配/复制与调度层 | M2–M5 | 热路径直接调用，复用缓冲，按阶段记录开销；无实际消费者不增加中间层 |
| 手机后台/热限制破坏任务持续执行假设 | M0/M8 | 可持久化进度、暂停恢复与真机压力验证，不依赖后台永久运行 |

## 5. 工期与状态维护

目前不承诺日历工期。M0 才能确定平台工具链、色彩交接和性能风险；服务/手机详细功能、人员并行度也未确定。早期专项的局部估计不能直接相加为三端总工期。

每阶段开始时拆出下一组可验收任务，并记录负责人、实际依赖和预计投入；只估计边界已清楚的工作包。阶段结束更新上表与证据链接，失败或缺环境要保留为未完成，不能将“代码已迁入”替代端到端验收。

建议记录格式：`阶段 / 状态 / commit / 已验平台与样片 / 验证记录链接 / 未验项与阻塞决策`。当前下一步为 M0 的基线与最小原型；本轮文档整理不自动启动代码改造。
