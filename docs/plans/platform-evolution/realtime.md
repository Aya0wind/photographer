# 本地实时编辑、RAW 代理与原生性能计划

返回 [方案入口](README.md)。适用于桌面和手机的本地处理，包括远程客户端下载代理后的本机编辑。Web 浏览器使用 [异步服务流程](collaboration-sync.md)，不套用本机帧率目标。

## 1. 执行链与数据合同

```text
打开资产 → 快速 JPEG/已有代理 → 当前配方 → 立即可编辑
    └─ 后台 LibRaw → 高精度线性代理 → 最新配方候选帧 → 原子切换

切换后：代理 / 中间结果常驻 → 更新参数 → GPU/CPU 处理 → 原生呈现
导出：完整原图 + 冻结配方/资源版本 → 完整质量处理 → 目标提交
```

生成 Smart Preview 仍访问 RAW，不能表述为“只有导出才读取 RAW”。代理保存线性工作值及颜色/精度/源尺度信息，不能以相机 JPEG 或普通显示 PNG 替代。高精度代理传输/存储格式在 M0/M5 验证后确定。

JPEG 包含机内风格，切换 RAW 代理可能改变基础颜色。只在候选完整帧就绪后切换，可平滑过渡但不能承诺无色差；RAW 代理就绪后才作为导出效果参考。

## 2. 逐类操作的更新范围

| 用户变化 | 应更新的阶段 | 应复用的数据 |
| --- | --- | --- |
| 曝光 | 线性曝光及下游 | 解码/去马赛克结果、代理源 |
| 胶片、Log/LUT 选择、强度 | 胶片输入转换/采样/混合及下游 | RAW 显影与源纹理；色域/传递合同变化才失效对应阶段 |
| 曲线、HSL、色彩分级、创意 LUT | 当前调整起的必要下游 | RAW、基础显影和未受影响的空间滤镜结果 |
| 蒙版笔迹/渐变 | 受影响覆盖区域和相关调整 | 不变源数据、其他蒙版/阶段；halo 范围按滤镜需要扩张 |
| 几何/视口 | 依合同调整变换或显示 | 未改变的调色结果；缩放/pan 不自动重新完整显影 |
| 锐化、降噪、清晰度、颗粒等 | 相应空间阶段及下游 | 前置颜色结果；尺寸/随机种子按源坐标处理 |
| 相机白平衡 | 可能影响去马赛克、相机矩阵与后续颜色 | 可复用传感器/解包数据；缓存有效性取决于具体 LibRaw 路径 |

缓存依赖从真实算法输入推导，不能仅按 UI 面板划分。新处理链与旧链顺序不同必须显式版本化。

## 3. 白平衡和空间滤镜

M0 验证低分辨率精确显影，以及线性缓存上的快速相对白平衡加精确更新两种候选。M5 根据实际延迟、颜色差异与内存选择，不预先承诺某一近似正确。

拖动时必须及时反馈最新参数；停止后精确更新若存在明显跳色，不满足默认体验要求。GPU 快速路径不得偷偷遗漏相机矩阵更新、重复白平衡或把 JPEG 相对白平衡说成 RAW 绝对白平衡。

空间滤镜按源像素尺度保持预览/导出足迹；分块保留 halo，颗粒使用稳定源坐标与种子。已有 CPU 实现先作为参考，只有热点与性能数据支持时才新增 GPU/SIMD 内核。

## 4. 多核与 GPU

- 原生数据用连续/可分块缓冲和明确步幅描述；只读共享与不重叠输出支持安全并行。减少整图复制、分配和无必要精度转换。
- CPU 用合适粒度的行带/瓦片和 SIMD；小图/短阶段可串行。Rust 池与 C/C++ 内部并行统一限额，不嵌套满载。
- GPU 缓存源纹理/LUT/中间结果，更新 uniform 或必要数据；按设备纹理/存储缓冲限制分块。移动端与独显的传输成本分别测量。
- 同设备呈现尽量避免读回→编码→IPC→解码；Web 异步输出仍需编码，这不影响本地实时路径。
- 能力选择区分 Auto/CPU/Force GPU。Auto 对可恢复失败可回退；Force 失败返回明确错误，实际执行后端进入诊断。
- GPU 失败结果不得半写提交；回退前等待/隔离在途资源，CPU 路径也领取预算。驱动丢失或不可控 native 故障需要宿主恢复，不能宣称所有错误均能无缝回退。

## 5. 调度、失效与生命周期

配方 revision、source revision、视图与处理资源版本分别标识。每会话合并高频请求，只呈现仍匹配当前版本的结果；耗时 native 调用无法立即取消时，结果丢弃且继续占有资源许可直到退出。

后台代理准备不能抢占全部 CPU/RAM/VRAM；开始前估算解包、去马赛克、中间 float 和纹理峰值。不得仅按最终 2048 像素代理大小估算。移动设备低内存时优先释放可重建缓存，并暂停重任务。

代理切换保留工具、视口、历史和蒙版源坐标，取色/直方图/剪切提示/前后对比同时切换有效来源。表面销毁后可重建 GPU 资源，配方和资产身份不随窗口消失。

应用进入系统后台后停止依赖可持续运行的假设，保存配方并按宿主许可暂停/恢复。多个用户的服务任务使用服务端公平预算；本地预算不需要用户角色模型。

## 6. 实施检查点

| 检查点 | 所属阶段 | 交付 |
| --- | --- | --- |
| RT0 | M0 | 现有处理分段、可见延迟、峰值内存基线；RAW/白平衡原型 |
| RT1 | M3/M4 | 预算统一、旧链共享、源纹理/阶段缓存复用，无行为回归 |
| RT2 | M5 | JPEG→线性代理最新帧切换、CPU 胶片参考与完整导出 |
| RT3 | M5 | GPU 胶片、多核/空间阶段优化、Auto/CPU/Force 对照 |
| RT4 | M8 | Android/iOS 表面、挂起恢复、热状态/低内存与同步并发 |
| RT5 | 后续 | 高分辨率视口/区域代理；小代理不能冒充 100% 原图细节 |

## 7. 验收目标与诊断

当前拟定：代表设备常用代理上，轻量调色可见更新至少 30 fps，输入到可见帧 p95 不超过 100 ms。尚未实测；白平衡和空间滤镜单独报告，未达标时保留为待优化，不把最终导出成功计为实时达标。

测量覆盖输入、排队、来源读取/下载、显影、代理缩放、颜色/滤镜、GPU 上传/执行/读回、编码和实际呈现；记录冷/热缓存、原图和代理尺寸、内存/显存峰值及后端。CPU 函数返回时间和 GPU 提交时间都不等于可见时间。

数值覆盖负值/超白、Log 分段、混合 0%、ICC、无重复曝光/WB/gamma、CPU/GPU、不同尺度、区域边界与导出对照。样片/设备限制与性能收益必须分别记录，详细矩阵见 [validation](validation.md)。
