# 选片（Culling）功能方案（2026-09-28，待用户拍板，未实施）

> 依据：用户需求（保存选片过程 / 选了多少 / 下次打开继续选 / 单独功能 / 结合像素蛋糕）
> + [像素蛋糕选片调研](2026-09-28-pixcake-culling-research.md)（含 Narrative Select / AfterShoot 参照）。
> 原则：AI 只建议不自动决定；进度全部从持久化真值派生（切页/重启不丢）。

## 0. 一句话

**「选片会话」作为一等持久化实体**：从相册/子组/筛选结果/导入批次一键开会话，全屏单图快速过片
（键盘流 + 对比视图 + 放大查焦位置跨图保持），每一步决定即时落库，随时退出、下次原位续选；
收尾时把「已选/已剔除」映射到现有的旗标/星级/子组/XMP 体系。

## 1. 数据模型（迁移 0024）

```sql
cull_session(
  id INTEGER PK, name TEXT,            -- 默认「<来源名> · 初选/复选…」
  scope TEXT NOT NULL,                 -- JSON：{kind:'album'|'query'|'import'|'session',
                                       --   albumId/subgroup | 查询快照+asset_ids | batchId | prevSessionId}
  order_key TEXT,                      -- 快照排序（拍摄时间序），续选定位用
  last_asset_id INTEGER NULL,          -- 断点（也可由 decision 覆盖推导）
  created_at, updated_at, finished_at NULL
)
cull_decision(
  session_id FK, asset_id FK,
  decision TEXT NOT NULL,              -- 'accepted' | 'rejected'（未定=无行）
  origin TEXT NOT NULL DEFAULT 'manual', -- 'manual' | 'ai'（AI 预标记，用户可翻转）
  decided_at INTEGER,
  PRIMARY KEY(session_id, asset_id)
)
```

- 进度（已选 x / 已剔除 y / 未定 z / 共 n）纯派生自 DB；「已看过」= 决定过的 + last_asset_id 之前的
- 会话归档不删（历史可查、可再开复选会话）

## 2. 会话来源（入口）

1. **相册/子组** → 相册页一键「选片」
2. **画廊当前筛选结果** → 快照 asset id 列表（防新导入扰动）
3. **导入完成** → 任务通知带「去选片」（≥150 张时主动引导，蛋糕同款阈值）
4. **上一会话的已选结果** → 建复选会话（初选→复选→精选多轮链，蛋糕无此机制）

## 3. 全屏选片界面（新 `src/features/culling/`）

### 3.1 单图过片（V1 核心，蛋糕单视图 + Narrative 键盘流）
- 键位：`←/→` 翻片 · `空格/↑` 选入 · `X/↓` 剔除 · `U` 清除决定（回到未定）· `1-5` 会话内星级（可选映射主库星级）· `Z` 按住放大查焦 · `?` 键位面板
- **放大位置跨图保持**（Narrative 杀手锏）：放大到眼部查焦，翻下一张保持同位置同倍率，直查同构图谁更锐
- 顶部进度条：`已选 12 · 已剔除 8 · 未定 337 / 357`；每步即写 DB，任意退出零丢失
- 底部胶片条：决定标记（绿✓/红✗）一目了然，可点击跳转
- 图上 AI 行内提示 chips：闭眼/失焦（现有 ai_analysis）；连拍堆叠徽标「组 5 张」+ 一键「本组只留这张」

### 3.2 对比视图（V2，蛋糕筛选视图）
- 同屏 2/3/4 张，默认取同连拍组；每张独立标记；与胶片条实时同步

### 3.3 AI 挑图规则（V3，蛋糕最有价值的弹窗，用我们自己的模型）
- 检测类型（闭眼/失焦；后续：连拍组自动留最锐 = AfterShoot 式）× 敏感度三档（映射 ai_analysis 阈值）
- 豁免规则（合影 >N 人不判闭眼等）+ 张数上限（「帮我精选 30 张」）
- 产出 = **预标记**（origin='ai'）写入会话，用户过片确认/翻转——不直接动主库标记（AI 只建议纪律）

## 4. 收尾出口

完成会话 → 结果视图（已选/已剔除两栏 + 数量）→ 用户选映射动作：
- 已选 → 旗标 P / 星级 / 加入子组（默认建议名「成片」）/ 写 XMP（走现有即时投影）
- 已剔除 → 拒绝态 X / 移入应用回收站（现有三级删除保护，含物理删除前列引用清单）
- 导出选中清单（清单文件，为将来 F 阶段网盘交付/客户远程选片预留）

远程客户选片（像素芝士式扫码）= F 阶段之后方向，本方案不做，出口已预留。

## 5. 对像素蛋糕的差异化

| | 像素蛋糕 | 本方案 |
|---|---|---|
| 会话保存/续选/进度 | 文档空白 | **核心特性**（一等实体+派生进度） |
| 多轮选片 | 教用户手动分轮 | 会话链原生 |
| AI 挑图 | 自动改标记（可保留手动） | 只做预标记，确认才落 |
| 计费 | 按张 | 全本地免费 |
| LR 工作流 | 独立生态 | 星级/拒绝/XMP/子组直连 |

## 6. 工程要点

- IPC：`cull_session_create/list/open/decide(批量)/rename/finish/discard` + `cull_ai_prescan`（规则跑批，V3）
- 前端：会话列表页（进行中置顶/进度徽标）+ 全屏选片层；键盘与查看器键位协调（选片层打开时接管）
- 规模：万张会话无压力（order_key 快照序 + 稀疏 decision 表）
- 后端决定批量写（过片快）+ 单条写（对比视图）同接口

## 7. 排期建议（拍板后执行）

- **V1**：数据模型 + 会话入口（相册/子组/画廊快照）+ 单图过片键盘流 + 进度/续选 + 收尾映射（旗标/星级/拒绝/子组）
- **V2**：对比视图 + 放大位置跨图保持 + 连拍组集成（一键留这张）
- **V3**：AI 挑图规则弹窗（闭眼通道上线后威力全开）+ 导入完成引导
