# 内存生命周期与峰值优化实施记录

日期：2026-10-13。覆盖查看器预加载、编辑预览、索引执行、AI 模型/聚类缓存和前端会话缓存。释放指解除应用持有的资源；不承诺浏览器、分配器或驱动的 RSS/显存统计立刻等量下降。

## 已实施的释放策略

| 资源 | 使用期间 | 退出 / 空闲处理 |
| --- | --- | --- |
| 查看器预加载 | 前后各一张屏幕代理图；当前主图仍按原有清晰度链路加载 | 切图、退出清除预加载 Image 的 src 和回调；迟到 IPC 结果不再创建解码图片 |
| 编辑生成帧 | 保留最多三个已解码帧，避免替换黑闪 | 关闭调度器释放图像引用、撤销 blob URL、清空帧数组；新旧会话迟到结果维持原有关闭检查 |
| 编辑会话 | 原有四会话 / RAW 预算；渲染使用 Arc | 正常 close 删除会话；后台每十秒检查原有三十分钟过期时间，置关闭标志后移除；忙碌会话使用 try_lock 跳过 |
| 独立 GPU 合成器 | 维持原有 256 MiB 缓存和四文档上限 | 最后一个编辑会话关闭后异步清文档；最后一次渲染结束满一分钟卸载设备；维护清理消息不延长空闲时间 |
| 索引分析图 / 检测结果 | 原有约 64 MiB 图像缓存和 128 项检测结果 | 三十秒未访问后后台清引用；在途消费者持有的 Arc 继续有效 |
| 人脸聚类缓存 | 按库共享；近期非活跃缓存最多四库，活跃持有者允许临时超额 | 一分钟未访问且没有外部持有者时清除；也纳入 AI 卸载 |
| AI 模型 / 向量索引 | 惰性加载 | 默认十分钟空闲卸载；服务在应用启动无条件创建，首次建库也有覆盖；使用代数防止卸载期间重新加载被误标为已释放 |
| 索引 worker | 工作时仍按物理核心数并发 | 十秒未执行有效任务后退出并释放连接；每库保留一个轻量协调器，按通知或三十秒退避检查重新启动 worker |
| 缩略图 URL / 失败状态 | 各自最多 2048 项，淘汰最早写入项 | 切库继续整表失效；这些缓存保存 URL/状态，不保存完整像素 |
| 画廊隐藏快照 | 最多 5000 个已加载资产 | 一分钟后清除；超大快照不保留，返回时重新加载，可能不保留原有深处滚动位置 |
| 编辑撤销历史 | 最近一百步、估算序列化大小八 MiB | 淘汰旧历史；超大单步不收入历史，当前配方仍保留；裁剪事务保持原有提交/取消语义 |

GPU 原生窗口已有停线程、销毁窗口路径，本轮从后端会话关闭和过期回收入口也调用该路径，不只依赖前端卸载回调。没有对浏览器调用强制 GC、对进程强制 trim working set，也不删除磁盘缩略图/代理缓存。

## 执行与兼容边界

- 新增索引瞬时内存准入，使用已有 FIFO Budget，默认 512 MiB，`PHOTO_HUB_INDEX_MEMORY_MB` 可覆盖（64–8192）。根据登记尺寸估算原图解码开销；未知尺寸按 256 MiB，超预算单任务独占额度执行，不永久等待。
- 该预算控制索引并发，不是进程总内存硬限制；模型、图像缓存、前台预览及解码器真实额外分配需另行计量。低内存设备的自适应 RAM/VRAM 预算仍需要实测后调整。
- worker 退出不删除任务、不重置 live owner；只有进程启动回收遗留 running。协调器比较通知代数与等待条件，关闭 worker 期间的新导入/继续/模型就绪通知不会丢失；paused、依赖未就绪、模型未就绪、退避任务不引发持续创建 worker。
- 新任务存在时协调器直接重新执行，不额外等待三十秒。所有 worker 退出后才进入协调等待，因此在途计算仍按原回执结算。
- ONNX 输入改用 TensorRef 借用现有连续缓冲区，减少图像和文本输入复制；缓冲区贯穿同步 Run 与 GPU→CPU 重试，不借出应用生命周期之外的指针。必要的结果拥有权转换保留。
- 缓存均可重建，清理不改变配方、索引持久结果或原照片。清理后的首次编辑 / 模型查询可能出现冷加载延迟。

## 验证与后续验收

相邻回归用例已补充：预加载释放与迟到结果、缩略图容量淘汰、快照定时释放、撤销容量、AI 卸载并发使用代数、分析缓存持有者保护、人脸缓存活跃引用保护、编辑会话过期围栏、索引暂停/退避唤醒和尺寸估算。

真实缓存回收、AI 卸载、GPU 设备卸载会写入现有轮换日志，仅在实际释放时记录，便于核对发生时间。

本轮只执行 TypeScript 静态类型检查、Rust 语法解析、diff 空白检查和改动影响检查；不在本机运行应用、构建或测试。Windows/macOS 编译交给 dev CI。上述单测尚未执行，未报告实测内存下降或吞吐收益。

实际验收需要分别记录 Rust 进程、WebView 进程和 GPU：

1. 连续浏览、快速切图、退出查看器；确认迟到预加载不解码，重复操作后保留量不持续增长。
2. 打开、连续编辑、关闭；确认 blob 帧和会话引用消失，GPU 最后一次渲染一分钟后卸载；长任务仍保留资源直到结束。
3. 导入并索引完成；检查 worker/连接、三十秒分析缓存、一分钟人脸聚类缓存、十分钟模型卸载的分阶段下降。
4. 空闲后再次导入、继续暂停任务、模型下载完成、重启续任务；确认恢复及时且没有过期回执覆盖活跃任务。
5. 首次启动无数据库，创建库后加载模型，再空闲；确认卸载服务仍生效。
6. 多库切换、GPU 故障 fallback、超大 RAW/TIFF、长时间笔刷编辑；检查峰值、首帧延迟和稳态吞吐。分配器保留的空闲空间与应用仍持有的缓存分开分析。
