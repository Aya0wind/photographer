# LibRaw 显影、Smart Preview 与胶片模拟实施计划

日期：2026-10-12。状态：方案已确定，待实施；本文不表示对应功能、画质或性能已经验证。

## 1. 目标与决策

保留 PhotoCraft 的编辑器能力，替换 RAW 解码与显影入口，并接入 RawLab 的胶片色彩处理。编辑器先使用内嵌 JPEG 快速响应，后台生成 RAW Smart Preview，准备完成后切换；导出从完整 RAW 生成最终结果。

所有现有常规编辑操作都必须在拖动期间提供连续可见反馈，包括曝光、白平衡、LUT、胶片模拟、曲线、HSL、局部蒙版、颗粒和暗角。交互链不得等待完整 RAW 显影或最终导出。实时性能以实机测量验收，不能由“使用 GPU”或“采用缓存”推定。

本轮实施方向：

- LibRaw 负责 RAW 读取、黑电平、相机白平衡、去马赛克及相关相机处理。
- 使用 RawLab 已有显影与色彩契约作为接入参考，按需要复用其 C++ 模块；不搬入完整客户端和无关算法。
- PhotoCraft 继续负责 RGB 调色、调整层、蒙版、合成、几何、标注、色彩管理和文件输出。
- 本项目负责编辑配方、历史、持久化、预览调度、代理缓存、源文件归属和导出任务。
- 不在本次项目中重写整套 PhotoCraft 编辑引擎。

本文更新 [PhotoCraft 编辑器移植计划](2026-10-10-photocraft-editor-migration.md) 的后续 RAW 方向：此前取消自动升级 RAW 预览是已完成的历史行为；新方案允许受控、可取消的后台代理生成与一次性切换，不允许每次调色重显影完整 RAW。

当前 `photocraft-raw` 是纯 Rust 实现，不依赖 LibRaw；当前版本输出 16 位、gamma 1.8 的 ProPhoto RGB，并在处理过程中裁剪部分数值。部分原生 RAW 缺少相机校准时使用替代原色，CR3、RAF、X-Trans 等存在支持限制。不能将这些结论外推到其他 PhotoCraft 版本。

`photocraft-algo::camera_raw` 还承担已经解码的 RGB 图像调色和空间滤镜；替换 `photocraft-raw` 不等于移除前者。现有显影注释中提到 rawler 的内容应在实际迁移时按调用链修正。

## 3. 预览生命周期

```text
打开照片
  ├─ 内嵌 JPEG / 已有快速代理 → 当前配方 → 立即显示并交互
  └─ 后台 LibRaw → 线性 RAW Smart Preview → 当前最新配方
                                           ↓
                              完整候选帧就绪后切换来源
                                           ↓
                         继续实时编辑，复用代理与 GPU 纹理

导出 → 原始 RAW → 完整质量显影 → 同一色彩/调色配方 → 编码与落位
```

这里的 Smart Preview 是本项目的高精度 RAW 编辑代理，不承诺与 Adobe Smart Preview 的格式兼容。生成它仍需读取、解码 RAW；“仅导出操作完整 RAW”指完整分辨率最终渲染，不表示预览阶段从不访问 RAW。

### 3.1 快速 JPEG 阶段

- 优先使用有效内嵌预览；不存在时使用已有代理，仍没有时异步生成可用预览。
- 正确处理方向和已知 ICC，缺少色彩描述时采用明确记录的默认约定。
- 编辑始终写入统一配方，不把处理结果逐次烘焙回 JPEG，不建立第二套撤销历史。
- JPEG 已包含机内风格、色调曲线和白平衡；胶片/曝光效果只作为临时反馈，不能声称与 RAW 导出一致。

### 3.2 后台 RAW 代理

- 缓存主体使用浮点线性 RGB 或经验证足够精度的表示；避免保存为有损 JPEG 或提前裁剪到显示范围。
- 首期工作色彩契约为线性 sRGB/D65，允许负值和大于 1 的工作值。矩阵、传递函数、方向、源尺寸、曝光基准必须随数据记录。
- 固定代理尺寸覆盖常用适屏编辑；初始候选长边为 2048，实际尺寸由质量、显存和性能测量决定，不随每次拖动改变。
- LibRaw 半尺寸模式与预览去马赛克可作为优化候选，但必须按 Bayer、X-Trans、裁切和方向分别验证；不能仅靠设置一个选项宣称低成本生成。
- 后台任务限制并发和内存，前台拖动优先；原片变更、切图、关闭会话后取消任务或丢弃过期结果。不支持中断的库调用只能标记过期，不能声称已停止计算。

### 3.3 原子切换

- 会话状态至少区分 `quick-preview`、`building-smart-preview`、`smart-preview-ready` 和失败状态。
- 候选代理必须应用当前最新配方并生成完整帧后再替换；参数变化时重算候选帧，过期 revision 不得呈现。
- 不重置缩放、平移、选中工具、蒙版坐标、正在拖动的参数或历史。
- 配方不变，仅增加 source revision，使必要的 CPU/GPU 缓存失效。
- JPEG 与 RAW 基础颜色可能不同。平滑过渡只能缓和切换，不能消除色差；通过简洁状态提示说明何时进入 RAW 代理编辑。
- 后台失败保留快速预览及全部编辑，允许重试；不能把失败代理标记为精确结果。

### 3.4 放大与细节

固定尺寸 Smart Preview 不提供完整 RAW 的 100% 细节。首期先验收全图调色；后续增加视口优先的高分辨率区域代理与分辨率层级。现有取色、直方图、剪切提示、对比原图必须使用同一有效来源，避免画面已升级而诊断仍来自 JPEG。

## 4. 色彩链、白平衡与胶片模拟

### 4.1 统一顺序

```text
RAW：LibRaw 相机处理 → 浮点线性工作 RGB
JPEG：ICC 转换 / 传递函数反解 → 浮点线性工作 RGB
                         ↓
                用户曝光 / 必要的白平衡调整
                         ↓
      中性显示分支          胶片分支：F-Gamut / Log → 胶片 LUT
               └───────────┬───────────┘
                  同一显示编码下按强度混合
                         ↓
        PhotoCraft RGB 调色、创意 LUT、蒙版与效果
                         ↓
           几何、标注、显示 ICC / 导出目标 ICC
```

具体保留的后处理顺序以现有配方为基础，通过版本化合同固定。PhotoCraft RGB 算法的编码假设必须逐项核对；不能因为 Document 带 ICC，就假定每个滤镜自动完成正确转换。

- 曝光在线性数据中执行，复用代理，不因每次拖动重新去马赛克。
- 富士胶片 LUT 不能直接应用于普通显示 RGB；输入色域和 F-Log/F-Log2/F-Log2C 必须显式识别。
- 胶片强度混合发生在相同显示编码下，0% 与关闭胶片完全连续；不重复添加 gamma 或中性曲线。
- 线性 sRGB → PhotoCraft 文档的交接必须携带匹配的编码/ICC，明确哪里进入显示范围。
- 普通创意 LUT、胶片 LUT 和最终显示 ICC LUT 分开管理，允许胶片与创意 LUT 叠加。
- RawLab 使用三线性 LUT 插值，当前 PhotoCraft 使用四面体插值；与 RawLab 对齐时显式选定方式并做数值对照，不宣称两者结果完全相同。
- 不自动将 RawLab 的 +0.7 EV 工作流基准套到旧项目；RAW 元数据基准、代理匹配和用户曝光分别记录，禁止叠加两次。

### 4.2 白平衡交互

完整质量 RAW 白平衡优先在相机通道、去马赛克前执行。LibRaw 现有流程下修改它可能触发重新显影。

首期验证两条候选路径：低分辨率精确显影，以及基于保留线性数据的快速相对白平衡反馈、拖动结束后精确更新。必须测量连续拖动的响应及精确更新产生的差异；若近似造成明显颜色跳变，不作为默认方案交付。不得将 JPEG 上的色温变化描述为恢复原始相机白平衡。

胶片、LUT、强度、曲线等下游操作不得使 RAW 白平衡缓存失效。导出以配方中的绝对白平衡/用户调整执行完整质量路径，防止重复应用。

### 4.3 胶片功能范围

首期候选：PROVIA、Velvia、ASTIA、CLASSIC CHROME、CLASSIC Neg.、PRO Neg. Std、ETERNA、ETERNA BB、ACROS、REALA ACE；提供选择、开关、强度和必要的预览缩略图。

优先复用 RawLab 的色域/Log 数学和可验证的 LUT 数据，逐像素胶片路径在 CPU 建立参考后接入 GPU。保留现有颗粒、暗角、HSL、锐化和降噪，避免首期引入另一套空间算法。DCP `.rlook`、通用 LUT 离线适配作为后续阶段，不阻塞首期。

第三方 LUT 的来源、分发条件和归属需按实际素材核实；代码许可证与素材许可分别记录。RawLab 当前原创代码声明为 GPL-3.0-only，Photographer 为 GPL-3.0-or-later；复用时保留相应声明和来源，不将第三方 LUT 视为原创代码许可覆盖的内容。

## 5. 配方、缓存与执行边界

- 配方记录渲染版本、显影后端、曝光基准策略、白平衡、胶片 ID/版本/强度以及现有 RGB 调整。
- 保存的项目不依赖某个临时代理路径；代理可删除和重建，原图与配方是持久化依据。
- 旧项目保留当前 PhotoCraft 解释与像素语义，禁止无提示地升级到 LibRaw。新方案使用明确的版本/后端标记，具体字段在实施时随迁移规则确定。
- 胶片资源使用稳定标识及内容版本；缺失资源明确提示，不静默替换成另一款胶片。
- 代理缓存键包含源身份、大小/修改时间及必要的内容校验、LibRaw/封装版本、显影质量、色彩合同、代理尺寸、曝光基准和白平衡等实际输入。
- LUT、强度、曲线与 HSL 等下游参数不进入基础代理键，只使相关下游阶段失效。
- 源数据、CPU 阶段缓存、GPU 纹理、后台任务分别设置内存/磁盘预算，按字节限制并实施淘汰，不能只限制条目数。
- GPU 交互尽量保持线性代理与中间纹理常驻，只更新参数；不能让整幅像素逐帧经 CPU 读回、JPEG 编码和 IPC。
- CPU 回退必须保持色彩/参数语义，并明确实际性能；使用 GPU 合成不等于所有空间滤镜已经 GPU 化。

## 7. 验证与性能目标

以下是拟定目标，尚未测量；验收必须写明机器、GPU、源文件、代理尺寸、冷/热缓存和实际呈现统计。

| 场景 | 验收目标 |
| --- | --- |
| 已就绪代理上的曝光、曲线、LUT、胶片/强度拖动 | 常用代理尺寸下可见更新目标至少 30 fps；输入到可见帧 p95 目标不超过 100 ms，过期帧不呈现 |
| 白平衡和空间滤镜拖动 | 持续提供最新参数的可见反馈；达不到同等目标时必须优化或记录专项方案，不能用导出完成代替实时验收 |
| 后台代理切换 | 不重置视口、配方、历史或工具；显示完整候选帧，不出现空白或旧参数回跳 |
| 首开与代理生成 | 分别报告首个可编辑帧、RAW 代理可用时间、峰值 CPU/RAM/VRAM；以阶段 0 基线确定预算 |
| 预览与导出 | 在 RAW 代理阶段、相同配方下对齐色彩和操作顺序；空间滤镜/低分辨率显影误差单独评估 |

验证样片至少包含 Bayer、X-Trans、DNG、不同压缩方式，亮部饱和、阴影、肤色、高饱和颜色、不同方向/裁切与缺失/异常元数据。按样片记录覆盖，不宣称所有机型均已标定。

数值测试覆盖色域矩阵、Log 分段、负值/超白、LUT 边界、强度 0%、CPU/GPU 对照及无重复曝光/WB/gamma。交互测试覆盖调色时后台完成、过期任务、资源变更、损坏缓存、GPU 失败、导出并发和旧配方回放。真实画质、实机性能和构建结果分别报告。

## 8. 工作量与保留 PhotoCraft 的理由

初步工程量按一名熟悉 Rust/GPU 的开发者、复用成熟组件估算：

- 保留 PhotoCraft，完成 LibRaw 接入、后台代理切换及首期胶片：约 3–6 人周；包含必要验证，不包含完整高分辨率区域系统、所有机型认证和所有空间滤镜重写。阶段 0 后重新估算。
- 若自研精简的基础摄影处理链：约 2–3 人月，需收敛现有功能。
- 若替代目前已使用的全部 PhotoCraft 能力：约 4–8 人月或更多，需要承担 GPU/CPU 一致性、空间算法、蒙版、ICC、格式与旧项目兼容。

这些是范围估算，不是交付承诺。Smart Preview 改变输入与调度方式，不会消除 RGB 调色、合成、GPU、色彩管理和导出的职责。先保留这些现有能力，按真实瓶颈逐项替换，避免将显影迁移扩展为完整编辑器重写。

## 9. 完成标准

完成必须同时满足：常规操作实时反馈、后台代理可靠切换、胶片色彩合同正确、完整 RAW 导出与代理共享处理语义、旧项目兼容、各目标平台有相应验证证据。仅新增面板、成功加载 LUT 或跑通单张 RAW 不代表整个方案完成。
