# PhotoCraft 高级编辑接入计划与第一版实现

## 定位与架构

高级编辑是面向照片资产的独立能力。现有简单编辑器保留原工具、布局、配方和算法。用户从图库/相册进入，保存编辑、生成成片、导回图库，不管理源文件或项目文件位置。

直接引用上游 `photocraft-engine`、`photocraft-compose`，固定提交 `3955bf4f1911a69ea08947634b3e2b459feece2f`（workspace 0.5.0）。不 fork、不修改上游源码、不引入 egui/独立程序。React UI 参考左侧工具、中央画布、右侧属性的布局，沿用应用的圆角、磨砂和深浅主题，画布维持中性深色。

前端只依赖本项目 IPC，上游 API 和命令集中在 `edit/photocraft.rs`。Document/Surface 逐行接收原有 RAW/EXIF 解码结果，避免 PNG 中转和整图 RGBA 副本。当前采用声明式配方：前端配方历史是唯一的交互撤销栈，后台从未修改的基础文档重建结果，不叠加第二套持久化 undo 栈。

LTO 可优化不可达代码，但动态命令注册可能保留未展示的功能。开发 release profile 继续保持原编译速度设置，不改变全项目优化策略。

## 第一版实现范围

以下已有代码接线，尚未运行应用、构建或测试：

1. 照片右键菜单和预览增加“高级编辑”；原“编辑”仍进入简单编辑。
2. 曝光、亮度、对比度、饱和度、自然饱和度、冷暖/色调、曲线及预设。
3. 裁剪、90° 旋转、文字/笔迹标注、同一构图原图对比、缩放和平移。
4. 高级编辑状态按库/资产保存，再次打开同一照片恢复，与简单编辑记录独立。
5. “保存成片并返回”：先保存编辑状态，再使用既有后台导出任务生成 JPEG、登记照片，成功后关闭工作区；失败保留编辑状态可重试。
6. 从相册进入携带相册和子组，默认导回原位置；图库照片仅属于一个相册时复用该相册，属于多个相册时选择目标；无来源相册时进入应用既有默认相册。
7. 支持选择其他相册/子组，以及显式导出成品到设备。原片不被覆盖。
8. “浏览图库”收起工作区后，可从图库拖入照片。默认打开拖入照片编辑；切换时处理未保存改动，提供保存并继续、放弃和取消。
9. 成片登记后刷新图库/相册列表和计数，遵循既有普通照片登记语义，不恢复已退役的 derived 分组。

冷暖/色调是 RGB 中间调色彩平衡，不是 RAW 传感器白平衡或 Kelvin 色温。文字和笔迹暂沿用原坐标/字体/栅格化契约，尚未提供自由图层编辑器。

## 与照片库存储重构的边界

不改 `db/*`、数据库迁移、照片布局、导入引擎、库迁移实现或源文件管理规则。

依赖边界只有当前库快照、资产查询、资产所属相册，以及既有导出任务/相册登记。资源解析集中在 `edit/project.rs::resolve`；导出工作线程的 DB 路径和照片根路径来自同一库快照。

高级编辑状态由 `edit/project.rs` 独立管理，在库数据目录新增 `advanced-edits/<assetId>.json`，含库 ID、资产 ID、配方版本和配方。此位置不向 UI 暴露，没有新增 SQL 表，也不修改简单编辑的 `edit_recipe`。现有库迁移为整目录迁移；未来重构需保留该目录，或替换 `resolve/project_path` 适配点。

前端携带进入时的库 ID，后台拒绝切库后使用旧资产 ID。切库时保留内存编辑，提示切回原库；源文件失效或被替换时重新准备预览。源路径只存在后台适配层，UI 始终处理资产。

共享修改限于 Cargo manifest/lock、命令注册、应用壳、照片入口和列表刷新。存储重构合并时核对 `edit/project.rs` 与既有导出边界即可。

## 预览与任务约束

- 每个会话只解码一次源图，缓存最长边 1600 的未修改文档。
- 滑块防抖 120ms，每个前端会话最多一个合成请求在途，旧结果不能覆盖新请求。
- UI 坐标以方向归一化后的原尺寸为准，代理图不改变裁剪/标注坐标基。
- 使用有界压缩 JPEG data URL，不经 IPC 传原尺寸像素；后续精细编辑改为二进制/分块传输。
- 缓存最多 4 个会话，空闲有效期 30 分钟，关闭/重试/卸载时释放。
- 编辑状态通过同目录临时文件原子替换；读取限 4MB，损坏明确报错，不静默重置或覆盖。
- 解码、合成、状态读写在阻塞线程执行；全尺寸合成按行带处理。
- 导出用既有任务事件和状态补偿读取，覆盖事件先于前端 job ID 到达的情况。
- 保存/生成成片期间限制冲突操作，关闭或切换前处理未保存状态。

## 后续阶段

1. 根据真实大图结果优化 1:1 区域预览、损坏区域更新、二进制传输、任务取消、内存预算。需要时接入 photocraft-gpu，不假设原生纹理可直接用于 WebView。
2. 引入独立图层模型/面板，再支持多照片合成、蒙版、选区和局部调整。多个源照片记录库/资产引用。
3. 将文字/画笔迁移到上游原生图层与工具，验证预览/成品字体和笔触一致性，继续保持简单编辑输出稳定。
4. 完整上游文档序列化在状态适配层引入，仍由应用管理位置，不向 UI 泄漏上游数据类型。

## 验证和交付

按用户要求，不运行应用、构建或测试。仅执行 TypeScript 检查、Rustfmt 语法/格式检查、Cargo manifest/lock 元数据检查和差异静态审查。Rust 类型及链接兼容性、Windows/macOS 效果、大图性能和色彩表现需 CI/人工验证。

人工验证重点：简单/高级状态隔离、保存恢复、旋转裁剪后标注、调整预览/成片、相册及子组导回、拖入切换、缺源/源替换、跨库同 ID、失败重试、深浅主题及快速滑块操作。
