# 导入向导流程与界面重设计

日期：2026-10-08。

## 目标

旧界面把来源树、文件选择和导入设置同时摆在三栏中，用户需要先理解布局再完成导入。新界面按操作顺序展示任务，挑选阶段尽量把空间留给照片，确认阶段才展示会影响文件处理的设置。

## 流程

1. **选择来源**：设备卡片、系统文件夹选择器和最近来源。普通入口不自动选择第一台设备；设备弹窗的深链可以直接进入对应来源的挑选页。
2. **挑选照片**：全宽缩略图或列表，保留按目录分组、组内勾选、全选、取消全选和反选。来源切换、展示方式与缩略图大小直接可见；刷新等次要操作收入菜单。标准与大缩略图分别使用 160px 和 220px 宽度。
3. **确认导入**：右侧模态抽屉选择相册和导入方式。新建相册在同一选择器内进入，只在需要时显示名称输入框。子组、去重、存储路径和第二份备份收入“更多导入选项”。
4. **后台处理**：明确点击开始后提交导入任务，返回图库继续浏览，任务进度通过全局任务抽屉查看。

挑选和确认之间可以返回，照片选择和设置保留。确认抽屉负责键盘焦点限制与恢复，支持 Esc、关闭按钮和点击遮罩返回；提交期间禁止重复点击与关闭抽屉。

## 文件处理规则

- 默认复制，已识别的相机和 SD 卡只允许复制。
- 普通外置存储保留复制、移动和引用方式；无法识别类型时默认复制，允许手动引用。
- 复制、移动和引用的说明在确认阶段直接展示；引用仍沿用已有的源失效处理。
- 第二份备份仅与复制方式兼容，启用后第二目标路径必填。
- 照片必须进入已有相册或新相册。新相册创建成功但任务启动失败时，重试复用已创建相册。
- 现有库级目录布局和并发规则保持，前端继续使用原有导入 API，后端校验不变。

## 状态与失败处理

- 来源断开后不回落到另一台设备，保留明确的不可用提示并阻止提交。
- 文件夹扫描显示等待状态；切换设备后，迟到的文件夹结果不能覆盖新选择。
- 页面卸载后，迟到的来源扫描不会重新切换页面。
- 初次进入来源默认全选；手动取消或调整选择后，扫描中新到达的照片不再自动勾选。重新全选则恢复自动包含新增照片。
- 从缓存来源恢复时正确结束文件加载状态，避免“继续”按钮被旧加载状态锁住。
- 重复点击的保护覆盖相册创建和任务启动全过程。
- 来源错误显式确认；相册与导入错误留在确认抽屉中，方便就地修改和重试。

## 代码组织

- `ImportWizard.tsx`：页面步骤和确认抽屉组装。
- `lib/useImportWizard.ts`：来源、选择、相册、导入参数及异步操作状态。
- `components/ImportSourcePicker.tsx`：来源入口。
- `components/ImportPhotoPicker.tsx`：照片选择与展示控制。
- `components/ImportReviewDrawer.tsx`：模态抽屉和焦点行为。
- `components/ImportReviewOptions.tsx`：相册、导入方式和高级选项。
- `lib/useImportLayout.ts`：只保留展示方式与缩略图尺寸偏好；旧三栏布局存储键不再参与界面布局。
