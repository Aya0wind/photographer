# Photographer 后续开发计划（阶段 0 盘点 + A–E 落地排期）

> 依据 [docs/implementation-plan.md](../implementation-plan.md)（用户路线图，2026-09-24 整理）与基础版本（Photo Hub，commit 3a8be7c 时点）源码实况盘点。本文回答两件事：①路线图每一项在基础版本里的真实现状（已有 / 需改造 / 未实现，附证据）；②后续开发的先后顺序与首批任务拆解。

## 0. 盘点结论（一览）

基础版本已远超「空壳」：导入/去重/索引/AI/性能四条主线相当完整。真正的结构性缺口有四个：**相册数据模型**、**原片-成片版本关系**、**网盘交付**、**基础编辑**。选片与 AI 则是「已有八成，补齐收尾」。

## 1. 排期原则

- 相册模型是后续一切（选片状态、成片关系、交付记录、协作）的挂载点 → **最先做**。
- 成片关系是摄影师工作流（LR 调色回导）的断点 → 第二。
- AI 增补（闭眼/失焦）复用现成推理管线与模型包框架 → 低成本插入。
- 联机/移动端/编辑/网盘为独立战线，按用户实际需要插队。
- 每阶段收尾跑真实工作流回归（真卡导入→LR 星级→成片回导）。

## 2. 阶段任务分解

### A. 相册数据模型与相册化导入（首批，预计 2 个迭代）

1. **数据模型**：`album`（稳定 id、名称、相册日期、目录名、封面）+ `album_item`（相册↔资产、显示序、相册级选片状态）+ 迁移 0015；`asset` 增 `album` 维度查询索引（`album_item(album_id, sort_time, asset_id)`）。
2. **目录模板扩展**：`{YYYY}/{MM-DD}` → 支持 `/{相册名}` 段（默认 `YYYY/MM/DD/相册名`，按路线图 §2.2）；**存量目录不动**（模板只影响新导入——需用户确认此语义）。
3. **导入向导**：增加「建立或选择相册」步骤（三入口共用）；相册名跨平台过滤+重名处理；跨日活动按相册日期归档、逐张保留真实拍摄时间。
4. **前端相册区**：侧栏「相册」真数据化（现有智能相册标签墙保留并存）；相册页=album_item 时间线；「所有照片/相册照片」双主入口。
5. **相册化筛选**：筛选面板加相册维度（含跨相册组合）。
6. RAW+JPEG 后续补导到既有拍摄记录（pair_id 已有，验证跨批次补对）。

验收：相机卡保留旧照片再导入新相册按规则跳过；同一天同名相册有提示；相册删除不删物理文件。

### B. 选片补全与原片-成片关系（预计 2 个迭代）

1. **选片**：颜色标签（xmp:Label 写回+LR 映射配置）、接受/拒绝状态（与星级分层）、应用内回收站（从相册排除→回收站→永久删除三级，永久删除前列出全部引用）、智能视图保存、批量反选。
2. **版本关系模型**：`photo_group`（一次快门逻辑组，吸收现 pair_id）+ `asset_relation`（derived_from/来源软件/版本号/匹配依据/确认状态）。
3. **成片导回流**：选 LR 导出目录→扫描→命名模板+原片名+EXIF 时间+序列号候选→pHash 相似度辅助排序→歧义人工确认→derived_from 落库；未匹配入「待关联成片」。
4. **视图**：相册页只看原片/成片/对照/无成片四视图；详情页版本切换；原片星与成片星分开存并标明写回目标。
5. **LR 交接检查页**：一页说明（导出建议设置/冲突提示/命名模板建议）。

验收：LR 导出 JPEG 回导后可原/成片切换；误匹配可人工修正且重启保持；成片导回不覆盖原片星级。

### C. AI 增补（可并入 A/B 并行）

1. 闭眼检测包（人脸裁剪→眼部状态小模型，输出有人闭眼/可能/不确定）——挂进现有模型包框架（第三包）+ ai_analysis 表。
2. 失焦/模糊标签（梯度快筛+可选学习式复核，运动模糊/浅景深不误判）。
3. 两包默认不装、按需下载（沿用整包管理）；AI 推荐与用户决定分层，不自动写 XMP。

### D. 视频深度 + 基础编辑（独立战线）

1. 视频元数据补全（时长/帧率/码率/编码入库，ffprobe 侧车）+ 高码率本地代理（可选生成）。
2. 非破坏基础编辑：裁剪/旋转/文字/画笔标注/尺寸调整/导出 JPEG（edit_recipe 配方，导出即派生成片版本，挂 B 的版本关系）。

### E. 联机拍摄与移动端（独立战线，先评估后立项）

1. `CameraBackend` trait + 能力矩阵；libgphoto2 Windows 实测（驱动/占用/打包）。
2. iPad 联机预览/导入、手机胶片测光（Tauri mobile）——先做技术验证原型再排期。

### F. 网盘交付（独立战线）

百度网盘适配器（官方开放平台接口核实为前置条件）→ 手动发布流（选版本/命名/预览总量/后台上传/进度重试/交付记录/分享链接）；接口不可用时回退本地交付目录。令牌入系统凭据库。

### G. 横切（随各阶段）

- `THIRD_PARTY_NOTICES.md` + 依赖许可清单（SigLIP2/rawler/turbojpeg/usearch/ffmpeg/DirectML 各记档）。
- 相册模型上线前做一次**真实工作流端到端回归**（真卡→相册导入→星级 XMP→LR→成片回导）。
- 性能基准（20 万级）按用户定案延后至真实数据积累后。

## 3. 待用户确认的决策点

1. 相册目录模板语义：新模板只影响新导入、存量不动，是否接受？
2. 「所有照片」与「相册」双主入口的默认落地页（现图库=所有照片）。
3. 阶段顺序确认：A 相册 → B 选片+成片 → C AI 增补并行 →（D 编辑 / E 联机 / F 网盘按需插队）。
4. 颜色标签的 LR 映射默认配置（红/黄/绿/蓝/紫 标准 LR 色标起步？）。
