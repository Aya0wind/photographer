## 0. 结论先行

| 调研问题 | 结论（一句话） |
|---|---|
| 选片在产品里的位置 | 不是独立模块，而是「**图库页面 + AI 挑图侧边栏 + 筛选视图**」嵌在修图主流程里，配合「像素助手」对话式挑图 |
| 照片来源 | 本地文件夹/RAW 导入建「项目」、联机拍摄、云项目（芝士同步）、Lightroom .lrcat 目录导入 |
| 界面形态 | 图库三视图：网格（默认，滑杆调 1–7 张/行）、单视图（大图）、**筛选视图**（同屏多张大图对比，与缩略图库实时同步、X 关闭动态补位） |
| 标记体系 | 星标 / 旗标 / 色标（三件套，AI 挑图结果自动映射到这三类标记上） |
| AI 辅助 | 有：闭眼/欠曝/过曝/模糊/重复 五类检测，各三档敏感度，带豁免规则；重复组可进「对比照片」模式 |
| 过程保存与续选 | 标记随项目持久保存（缩略图常显标识），但**没有公开文档化的「选片会话保存/恢复/已选 x/y 进度条」**——这是蛋糕文档的空白点 |
| 结果出口 | 标记 → 精修页筛选器筛出 → 修图 → 导出（按张计费）；或「上传至选片交付」推给像素芝士做**客户微信扫码远程选片**，结果回传蛋糕形成闭环 |
| 计费 | 按导出张数计费的年费套餐；**四档套餐功能权益完全相同**，选片能力不分付费档；AI 挑图本身是否扣张数未核实（推断不扣） |

## 2. 摄影师端选片工作流（核心）

来源：[工作区页面功能说明 guide/9379](https://wiki.pixcakeai.com/guide/9379.html)（官方操作指南，2026-05-18）。

### 2.1 入口与项目结构

- 选片不是独立 App/模式，而是**项目内的工作流阶段**。主页导航：主页（云标识项目）/ AI 工具箱 / 本地项目 / 云空间（个人/团队）/ 工作流 / **选片交付**（通往芝士）/ 回收站（30 天可恢复）。
- 照片来源（建项目即导入）：
  - 本地文件夹/RAW 拖入主页自动按文件夹名建项目（什么值得买教程与 [efficiency-tools/16563](https://wiki.pixcakeai.com/efficiency-tools/16563.html) 口径一致）
  - 联机拍摄（多机型支持，含 FTP 联机，见 [guide/16810](https://wiki.pixcakeai.com/guide/16810.html)）
  - 芝士云项目同步（见 §5）
  - Lightroom .lrcat 目录级导入（可带出收藏夹与基础调整，[efficiency-tools/16563](https://wiki.pixcakeai.com/efficiency-tools/16563.html)）
- 进入项目后默认落在「精修页面」，顶部可切换 **图库 / 精修 / 创意** 三个页面。选片主要发生在图库页面。

### 2.2 图库页面（选片主界面）

| 要素 | 细节 |
|---|---|
| 视图 | **网格视图**（默认；左侧滑杆调每屏张数，每行最多 7 张、最少 1 张）；**单视图**（大图）；**筛选视图**（同屏对比多张） |
| 筛选视图细节 | 与缩略图库**实时同步选中状态**；每张图带 AI 精选标签、旗标、星标、色标与「**X**」关闭按钮；支持**动态补位**（关闭一张后其余补位） |
| 缩略图标识 | 每张至多 6 种：上方＝RAW 图 / 已导出 / 已编辑；下方＝旗标 / 星标 / 色标（设色标后缩略图框背景染色） |
| 显示开关 | 显示 RAW 格式 / 显示修图状态 / 显示导出状态；「全效果模式」开＝效果图、关＝原图 |
| 侧边栏 | **AI 挑图**、预设、元数据 |
| 其他 | 批量删除、导入新图、筛选、排序 |

### 2.3 AI 挑图（智能选片）

来源：[AI挑图怎么用 guide/9391](https://wiki.pixcakeai.com/guide/9391.html)（官方操作指南，2026-05-18）。这是与 Photo Hub 最直接对口的功能。

**入口（四个）**：
1. 图库页面右侧「开始 AI 挑图」，弹窗中设置规则；
2. 精修页面下方功能栏「去挑图」；
3. 单次导入 **≥150 张**时系统弹窗询问是否去挑图（主动触发时机）；
4. 像素助手对话指令（见 §2.4）。

**规则弹窗内容**：
- **场景选择**（10 种）：通用 / 人像 / 证件照 / 活动 / 婚礼 / 家庭 / 儿童 / 学校 / 孕妇 / 私房；
- **AI 精选**：评估表情自然度、肢体姿态、画面美学、构图合理性；可设**精选数量上限**，可选「挑出更多正脸照片」；
- **标记映射**：AI 结果自动打**星标/色标/旗标**（用户选其一），勾选「保留已设置的标签」则已有手动标签不被 AI 覆盖。

**五类检测项**（各支持 弱/标准/强 三档敏感度）：

| 检测 | 行为 | 豁免/细分规则 |
|---|---|---|
| 闭眼 | 打标签 + 归入「闭眼分组」 | 可勾选「大笑照片」「合影超过 X 人」不检测闭眼 |
| 欠曝 | 归入欠曝分组（判据：信息丢失且后期无法还原） | — |
| 过曝 | 归入过曝分组 | — |
| 模糊 | 检测晃动/运动/快门过低导致的人脸模糊 | 可勾选「至少一张人脸清晰则不标模糊」 |
| 重复图片 | 相似图归组 | 敏感度分「重复-标准-相似」三档；组内点「**对比照片**」进入筛选模式逐一对比挑选 |

**结果消费**：挑图完成后右侧「AI 挑图分组」面板查看各分组；回到精修页，**左下角筛选器按标记筛出 AI 精选照片**进入后续修图/导出。

### 2.4 像素助手（对话式挑图，9.0+）

来源：[像素助手怎么用 guide/16823](https://wiki.pixcakeai.com/guide/16823.html)（官方操作指南，2026-08-19）。

- 指令示例：「帮我做 AI 挑图，选 30 张」→ 弹设置卡片（精选数量 + 检测规则勾选）→ 确认后自动分析筛选并统计结果；
- 端到端：「把桌面上的照片挑 30 张修好导出」→ 自动拆解为 导入→AI挑图→筛选→修图→导出 五步计划；
- 联机：「开启联机拍摄，边拍边挑」→ 实时收图并自动标记闭眼/过曝等，**动态刷新筛选结果**；
- 偏好记忆：挑图张数、筛选规则存入偏好，未说明时沿用上次设置；
- 结构化卡片：导出路径、**扣费确认**等关键环节弹卡片让用户勾选确认。

### 2.5 多轮选片 / 对比 / 放大查焦

- **多轮**：产品内无显式「初选/精选」多轮会话；官方方法论文章（[efficiency-tools/16527](https://wiki.pixcakeai.com/efficiency-tools/16527.html)，2026 年）教用户「第一轮快速淘汰（闭眼/虚焦/遮挡）→ 第二轮按用途分层（主图/备选/氛围/记录/问题图）」，落地方式就是**标记 + 筛选器反复过滤**，即多轮靠用户自己用星标/色标组合实现。
- **对比视图**：有。精修页缩略图区有「单视图/对比视图/参考视图」切换；图库有筛选视图同屏对比；重复组有专用「对比照片」模式。
- **放大查焦**：精修页画布有显示比例调整/抓手工具，可放大看图；但**选片流程中专用的「放大锁定位置 + 方向键跨图查焦」能力未见文档**（Narrative Select 有此能力，见 §7）——**未核实**。

## 5. 选片结果出口与客户远程选片

### 5.1 摄影师侧出口

- **筛选 → 修图 → 导出**：精修页筛选器按星标/旗标/色标/AI 精选筛出后批量修图导出；导出消耗「蛋糕张数」（计费见 §6）。
- **Lightroom 往返**：可导出回兼容 .lrcat（目录级集成限制：RAW 不能以 RAW 导出、变换/镜头校正等不传输，[efficiency-tools/16563](https://wiki.pixcakeai.com/efficiency-tools/16563.html)）。
- 直接「复制/移动选中照片文件到某文件夹」的选片专用出口：**未核实**（文档只描述导出，未见 cull-to-folder 出口）。

### 5.2 客户远程选片（像素芝士闭环）

来源：[蛋糕——芝士交付选片 guide/16839](https://wiki.pixcakeai.com/guide/16839.html)、[蛋糕连接芝士 guide/16937](https://wiki.pixcakeai.com/guide/16937.html)（官方，版本要求：蛋糕桌面版 7.3.0+，芝士 1.6.0+）。

流程闭环：
1. 蛋糕导出项目时勾选「**上传至选片交付**」（iPad 版为「同时创建交付云相册」）；
2. 云传输列表实时查看上传；首页左侧「选片交付」进入交付项目页；
3. 右上角「**选片分享**」生成**二维码**，顾客**微信扫码进小程序**选片；
4. 两种模式：**在线交付**（所有项目可用，顾客查看/下载）与**在线选片**（仅「图片存云端」的云项目可用，顾客实际挑选）；
5. 选片结果与备注回传：交付项目页查看结果；点「去修图」打开对应蛋糕项目，**精修页可筛出已选照片、右侧面板定位选片备注**；
6. 精修后再导出勾选「上传至选片交付」会**替换**交付项目中的初修图，顾客在原小程序直接下载成品。

芝士侧补充（[pixcheese.com](https://www.pixcheese.com)，2026-09-28 抓取）：芝士同时是照片直播平台（AI挑图→AI修图→审核发布流水线、付费下载变现、人脸识别聚人、批量购买、团队角色：创建者/审核员/修图师/摄影师）。同步开关在芝士项目设置里（「同步项目至像素蛋糕」），图片、修图参数、图片状态（已选片/未选中）实时同步。

## 7. 同类工具参照（一页概览）

### 7.1 Narrative Select（辅助人工挑选派，narrative.so）

来源：[官方快速上手教程](https://narrative.so/select/lessons/quickstart-guide)、[AfterShoot 竞品对比页](https://aftershoot.com)（2026-07）、第三方评测（shotkit/SLR Lounge/Fstoppers，经搜索摘要）。

- 定位：**AI 辅助人工挑选**，不自动淘汰——AI 只标记问题（闭眼、失焦），每张去留由人决定；
- 招牌能力：**Close-ups 面板**——自动检测人脸并排显示每张脸的放大特写，不手动放大就能查表情/对焦；
- 场景/连拍分组：相似图与重复帧归组，可整组对比；
- **键盘流**是效率核心：官方称鼠标打分每张耗 1–2 秒，2000 张婚礼片必须用快捷键；快捷键可自定义；**放大状态下方向键切图保持同一放大位置**（跨图查焦）；
- 兼容 Lightroom 式打分/旗标按键习惯。

### 7.2 AfterShoot（自动挑选派，aftershoot.com)

来源：[cameronandtia.com 教程](https://cameronandtia.com)、[43addict 评测](https://43addict.com)、[imagen-ai.com 对比](https://imagen-ai.com)（2025–2026）。

- 定位：**自动挑选（auto-cull）**：重复组自动比较并每组交付 1 张最优帧（选最锐的）；
- 模糊/闭眼检测带**敏感度阈值**可调，能区分「故意动感模糊」与废片；图片有评分；
- 结果**导出到 Lightroom 目录时带上星级/色标/旗标**，选片结果直接变成 LR 里的标记；
- 新版把 cull + RAW 编辑 + AI 修肤 + 客户画廊打包为一体（与蛋糕「一个程序走完」思路趋同）；
- 近期改进：区分「有意变化」与「真重复」，挑选收紧约 20%。

### 7.3 中文同类（筑牛选片 / 灵枝选片）

多轮搜索**未找到可靠公开资料**（官网/帮助文档均未检索到）——**未核实**，不硬凑。中文市场可查的「客户在线选片」形态即像素芝士（§5.2）与靓选等影楼选片系统（仅下载站收录条目，未深入）。

## 8. 对 Photo Hub 的可借鉴点 / 不可照搬点

Photo Hub 现状：本地照片库应用，已有相册/子组、星级/旗标/拒绝 + XMP、AI 失焦标签、闭眼检测（在建）、连拍分组。

### 8.1 可借鉴（按价值排序）

1. **筛选视图（同屏多张大图挑选）**：蛋糕 9.1 专门为选片加的视图——同屏对比多张、与网格选中状态实时同步、每张带「X」关闭、动态补位。Photo Hub 已有标记体系，缺的就是这个「挑选专用视图」；实现要点是**与现有网格双向同步**而不是孤立的界面。
2. **AI 挑图的规则弹窗形态**：场景选择（人像/婚礼/儿童…）→ 检测项开关（闭眼/模糊/欠曝/过曝/重复）→ 每项**三档敏感度** → **豁免规则**（大笑不判闭眼、合影超 X 人不判闭眼、至少一张脸清晰不判模糊）→ 目标张数上限 → **AI 结果映射到用户自己的标记体系**（星/旗/色三选一）→「保留已有手动标记」开关。这套「可解释、可调、不越权」的 AI 规则 UI 对 Photo Hub 的失焦标签/闭眼检测落地直接可用，且豁免规则是减少 AI 误报抱怨的低成本手段。
3. **触发时机**：导入 ≥150 张时主动弹窗问「要去挑图吗」。Photo Hub 可在导入完成/连拍分组完成时做同样的主动引导。
4. **重复/连拍组的对比模式**：蛋糕对重复组提供「对比照片」进入筛选模式；Photo Hub 已有连拍分组，补一个「组内对比挑选」即闭环，与 Narrative 的场景分组思路一致。
5. **AI 结果即分组面板**：挑图完成右侧按「闭眼/欠曝/过曝/模糊/重复」分组呈现，让用户逐组复核——比一次性全自动淘汰更可信（Narrative 的「辅助不代决」哲学同理）。
6. **联机边拍边挑**（远期）：像素助手支持联机拍摄实时标记问题图动态刷新筛选；与本项目 tethering 调研（[2026-09-28-tethering-evaluation.md](./2026-09-28-tethering-evaluation.md)）天然衔接。
7. **键盘流优先**：蛋糕快捷键面板「可搜索 + 可自定义 + 核心键锁定」的设计值得抄；但更应借鉴 Narrative——把「放大锁定位置 + 方向键跨图查焦」「LR 式 P/X/0-5 按键」作为本地桌面选片的默认效率路径。

### 8.2 不可照搬

1. **项目制 + 云空间 + 按张计费**：蛋糕的一切围绕「项目」与云协作，选片会话寄生在商业修图流程里。Photo Hub 是本地库，选片应直接基于现有**相册/子组**发起，无计费、无云端依赖。
2. **客户远程选片小程序闭环（芝士）**：重服务端生态（二维码、微信小程序、角色权限、付费下载变现）。Photo Hub 的对应物应是轻量本地出口：**导出选中清单/复制选中照片到交付目录**（与 [2026-09-28-netdisk-evaluation.md](./2026-09-28-netdisk-evaluation.md) 的 provider 无关交付底座正好衔接），客户侧分享不做或后置。
3. **对话式选片（像素助手）**：依赖云端大模型与账号体系，本地应用不适用；但其「偏好记忆（沿用上次挑图张数与规则）」可以低成本吸收进本地 AI 挑图设置。
4. **修图软件内嵌选片的界面包袱**：蛋糕图库/精修/创意三页同权，选片视图要和修图工具栏共存。Photo Hub 选片是主场景之一，界面可以更纯粹（大图流 + 标记 + 组对比），不必带修图工具栏。

### 8.3 蛋糕的文档空白 = Photo Hub 的差异化机会

- **选片会话的保存/续选**与**「已选 x/y」进度展示**：蛋糕公开文档完全未覆盖（§4）。Photo Hub 若做「显式的选片会话：进入/中途退出自动保存/下次继续/常驻进度计数 x/y/完成时汇总」，即是超过蛋糕文档化体验的明确差异点。
- **选片专用键盘细节**（哪些键干哪些事）蛋糕不公开；Photo Hub 应把快捷键作为一等公民写进文档（参考 Narrative 的 quickstart 做法）。
- **cull-to-folder 出口**（把选中照片复制/移动到新文件夹）蛋糕未见文档化；Photo Hub 作为文件系统上的本地库，这是最自然的出口，务必做。
