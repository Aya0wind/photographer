# 重构:单数据库多照片库(大一统)

> 2026-10-09 与用户逐条定案。取代现行「多库=多 SQLite(dbDir)+photoRoot 成对注册」模型。
> 版本未发布:**不做兼容、不做迁移、不带历史包袱**(用户红线)。

## 一、核心模型

- **应用级唯一数据库**(SQLite + 缩略图 + 向量 + 人脸),默认放应用数据目录;设置项「数据库位置」可改(Windows 数据盘需求)。
- **照片库 = 一个文件夹的登记项**(纯物理概念):N 个,由 `photos_libraries` 表管理。
- **相册/子组 = 纯逻辑概念**,数据库全局,不分库、无物理足迹;变更归属零文件操作。
- **无移库操作**:`assets.library_id` 静态属性,仅整库重定位时改库 root(归属不变)。
- 画廊 = 单一全局视图,照片跨库混排;「来自哪个库」是可筛选的存储属性,不可操作。

## 二、数据层

- `photos_libraries`:id(uuid)/name/root_path/created_at/status(online|offline)/照片数与容量缓存。
- `assets` 增加:`library_id`(索引)、`missing`(单文件缺失标记)、`xmp_dirty`(离线期间元数据改动待补写边车)。
- 相册/智能相册/人脸/向量:全局;vectors.usearch 单文件混布(asset id 全局 uuid,无需改)。
- 缩略图:应用数据目录统一 `thumbs/`(键=路径哈希,跨库安全)。
- settings.json 只留应用级设置;libraries 注册表、dbDir、activeLibrary、migrate 体系、新库并发首开迁移锁全部删除。
- schema 单版本:建表脚本即唯一版本,不写 migrate。

## 三、物理布局与导入

- **落盘布局 = 纯时间**:`{照片库}/{拍摄年}/{拍摄月}/{原文件名}`(EXIF 时间,缺失回退文件时间)。物理层无相册/子组维度。重名走现有 rename 策略;边车与本体同名跟随。
- **新建照片库**:登记空文件夹,之后 copy/move 导入目标 = 该库 root,按上述布局落盘。
- **从已有文件夹建立照片库**:reference 登记(只登记不搬文件),递归扫描、哈希同库内去重照旧、**目录结构不映射相册/子组**(不可控结构不猜),平铺登记;星级/颜色/关键字从 XMP 边车读入。
- **手动往库文件夹放文件**:自动识别——后台增量扫描(目录 mtime 剪枝,复用 reconcile 骨架 + 索引让路闸),新文件进未分组 + 边车读入,登记后通知;消失文件标 `missing`。只认可识别图片扩展名,忽略隐藏/系统目录,只登记绝不移动/重命名用户文件。
- **增量扫描去重(两级识别,导出到库内等场景)**:资产登记时记录 `卷序列号+文件 id`;新文件先查 file-id 索引,同卷同 id = 硬链接(库内导出物)→ 零哈希成本直接跳过;file-id 不可用(exFAT/FAT)或未命中 → 算哈希,与**同库**已有资产同内容 → 现有 duplicatePolicy(默认 skip)。同库同内容 = 不登记,复用导入去重规则;跨库不去重定案不受影响。用户手工复制文件夹进库同此规则。
- **被跳过的路径对库完全不可见**:不登记 → 不在画廊、不占索引、不生成缩略图、rating_watch 不监视(导出目录里 LR 随便改不回写库);其中 `.xmp` 无登记本体对应,按附属文件规则忽略。
- **删除语义(硬链接定案)**:删除/清空回收站 = 移除库内名字 + 资产记录,不做链接计数检查、不提示——数据生命周期交给文件系统硬链接语义(删一边名字另一边完好,库不误报缺失)。库内名字删除后,导出目录里的存活名字下次扫描无同哈希资产 → 自然重新登记(孤儿回收,无死区)。
- copy/move 导入目标选择 = 选照片库(替代现 targetRoot);双目的地 secondTarget 照旧。

## 四、跨库重复(同内容不同库)

- 数据层:不去重,独立资产独立 id(跨库重复是合法状态)。
- 导入/登记:同库内才触发 duplicatePolicy;跨库重复照常登记,完成后总结提示「N 张与其他照片库内容相同」。
- 显示层:「隐藏跨库重复」开关(默认关),按哈希分组,每组显示一张,优先级 = 在线 > 有高清 RAW > 评分高 > 导入早。
- **折叠 = 纯显示过滤**:操作只作用于可见资产,隐藏副本不变;「重复项」列表可看全部。

## 五、缺失处理

- 两级:整库离线(`status=offline`,reconcile 按照片库粒度)/ 单文件缺失(`missing`;检测 = 库上线校验 + 后台低频扫描 + 访问时惰性)。
- 缺失资产:画廊显示(缩略图缓存)+ 缺失角标可筛选;查看器仅缓存分辨率;评分/标签可改(进库);`xmp_dirty` 置位,库恢复在线后 reconcile 补写边车、清标志(与 rating_watch 读入方向对称闭环);编辑/导出/AI 重建跳过。
- 清空回收站:只对在线库真删本体;离线库回收站项原样保留 + 提示,不做「强制仅删记录」。
- 叠加场景:重复组优先显示在线项,全缺则显示一张带角标;缺失副本改评分走 xmp_dirty;各副本独立互不串。

## 六、LR 互操作

- **LR → Photo Hub**:自建目录整文件夹 reference 登记,边车星级/颜色/关键字读入,智能相册按条件建。
- **Photo Hub → LR**:选中相册/子组 → 「导出为文件夹」:同卷硬链接(秒级、零拷贝)/跨卷拷贝 + 写全量 XMP 边车 → LR 引用导入。导出物为快照,双向修改互不影响(硬链接 inode 语义天然保证)。
- 导出对话框默认建议库外路径(记住上次位置);目标选在任一照片库内 → 不禁止,提示「该文件夹会被扫描忽略(内容与库内重复),建议选择照片库外」;库内目标必然同卷必然硬链接,行为已被两级去重闭合。
- 应用间互操作只靠「文件夹 + XMP 边车」这对 LR 原生介质。

## 七、UI

- 左侧导航新增**「存储」页**:照片库卡片(名称/路径/在线状态/照片数/容量)+ 新建、从文件夹建立、在系统中打开、重定位、移除登记(问是否连记录删,**永不删照片文件**)。
- Onboarding 重构:数据库就位(默认应用目录)→ 引导建立第一个照片库(新建或选已有文件夹)。
- 退役:LibraryPickerPage、NewLibraryDialog、顶栏库切换、「库」文案全面改「照片库」。
- 画廊等页面默认全局,可按照片库过滤。
- `purge-user-data.ps1` 简化为只清应用数据目录(照片库根永远在用户文件夹,安全闸天然成立)。

## 八、边界场景定案(2026-10-09 用户确认的操作组合穷举)

1. **missing 哈希重绑(最重要)**:同库去重 skip 仅当存在**在线**同哈希资产;新文件命中 **missing** 资产哈希 → 判定为移动/改名,**重绑路径**(更新路径、清 missing、边车补写新位置、缩略图按内容复用)并通知。覆盖单文件改名与整文件夹重命名批量场景。删本体后放回**同名不同内容**:恢复时校验哈希,不一致按同路径新内容重算索引、保留逻辑元数据并提示。
2. **文件稳定度探测**:增量扫描跳过 mtime 距今小于冷却窗(约 10s)、两次探测间大小变化、或写入者持锁打不开的文件;大文件夹拷贝期间逐步拾取,最终收敛。
3. **晚到边车补读**:已登记资产后续出现同名边车且 mtime 晚于登记时间 → 触发一次边车读入(与 rating_watch 同路径),防 LR 文件夹边车后到静默丢星级。
4. **本体写回原子替换铁律**:库内照片本体的一切写回(含 JPEG 元数据段改写)必须「临时文件 + rename」——rename 只换名字指向,旧 inode 留给硬链接导出物(快照成真),且崩溃安全。落地时检查现有 img-parts 改写是否原地 patch,是则改掉。
5. **登记单管道**:增量扫描发现与导入落盘产出进同一登记队列串行处理(复用让路闸骨架),防双写竞争与重复算哈希/缩略图。
6. **root 校验**:各照片库 root 之间不得相同或互相包含;root 不得与数据库目录相同或互相包含(防把 thumbs/ 缩略图登记进库)。
7. 边界规则:扫描不跟随符号链接/junction;missing 标记延迟确认(连续两轮不在才标);macOS 大小写不敏感卷的同文件异名路径由同库哈希去重收敛。

## 九、UI 约束(用户红线)

- **新增「存储」页等一切 UI 严格遵循现有设计体系**:tailwind 语义色(bg-bg/text-text-*/border-edge/accent)、现有间距与圆角节奏;组件复用现有 Dialog/ContextMenu/ErrorModal/OverlayScrollArea,不引入新 UI 库、不发明新风格。
- 动画遵守现有设置开关体系(三件套+合成层纪律);路由仅入场。
- i18n 五语言全量补键,插键后 JSON 校验;data-testid 命名跟随现有规范。
