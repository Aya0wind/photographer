# 高级编辑器色彩与界面统一方案

日期：2026-10-16。状态：第一批色彩与日常界面已接线，尚未完成运行及画质验收。

本文合并本轮 Lightroom 功能对比、界面优化和默认 RAW 色彩讨论，作为后续高级编辑器工作的执行清单。现有接线记录仍见 [高级编辑器 Roadmap](../roadmaps/advanced-editor.md)、[RAW/Smart Preview 专项方案](2026-10-12-libraw-smart-preview-film.md)及[原生画布说明](../advanced-editor-native-canvas.md)。本文细化编辑器产品范围与色彩合同，不替换多端共享核心的模块边界。

用户当前要求不编译、不运行测试。本轮实现仅做源代码与静态检查；本文的运行、画质与设备验收项均为后续待执行项目，不表示已经验证，也不据此自行启动验证。

## 1. 已确定的方向

- 采用“机型校准、基础呈现、创意风格”分开的设计。建立自己的配置，不复制或命名为 Adobe Color，不承诺复现 Lightroom 或相机直出。
- 机型校准自动选择受支持的矩阵和拍摄白平衡；基础呈现首期提供标准、柔和、中性；现有胶片模拟和创意 LUT 保留。
- 优先统一基础 RAW 显影。胶片开关不再切换 RAW 解码器、去马赛克方式或基础校准来源。
- 继续使用固定版本 RawLab/LibRaw 的 RAW 能力和 PhotoCraft 的调色、蒙版、合成、几何、CMS 与输出能力；不重写整个引擎。
- 保留 JPEG 先显示、后台生成 RAW Smart Preview、导出完整 RAW 的交互路线。普通参数拖动不触发完整 RAW 重显影。
- 先保证正常调色和交付顺畅，再补常规工具，AI 和多图合成分批推进；不把全部 Lightroom 功能塞进第一批。
- 本方案中的一致性首先指同一照片、同一配方版本的预览与输出语义一致；不同机型、光线、显示设备不保证视觉完全一致。

## 2. 色彩处理合同

### 2.1 三层职责

| 层级 | 职责 | 首期范围 |
| --- | --- | --- |
| 机型校准 | 传感器解码、黑白电平、拍摄白平衡、去马赛克、机型矩阵与曝光基准 | 复用 RawLab/LibRaw；记录缺失校准和降级来源 |
| 基础呈现 | 把工作数据转换为可观看的颜色与明暗关系 | 标准、柔和、中性三套版本化配置 |
| 创意风格 | 胶片效果和用户选择的其他风格 | 复用现有内置/导入胶片与创意 LUT，遵循各自输入输出合同 |

基础校准不提供“随意挑选另一款相机矩阵”的普通用户入口。后续可增加显式自定义 DCP/ICC 输入配置；其设备、白平衡与色彩合同需要独立校验，不能把任意 ICC 当成相机配置使用。

### 2.2 统一处理顺序

```text
原始 RAW
  → 统一的 RawLab/LibRaw 解码、去马赛克、拍摄白平衡与机型校准
  → 浮点线性工作 RGB，记录原色、白点、曝光基准和方向
  → 用户曝光与白平衡调整（每项只应用一次）
  → 基础呈现分支 / 胶片显影分支
  → PhotoCraft 调色、曲线、HSL、局部蒙版、创意 LUT、效果
  → 几何与标注
  → 显示配置转换 / 导出目标 ICC 与编码
```

- 首期保留现有线性 sRGB/D65 工作合同，浮点值允许负值和大于 1；“线性 sRGB”不等于提前裁切到屏幕 sRGB。
- 主要编辑阶段逐项审计工作空间与编码假设，消除无意的 0..1 裁切及过早量化；只有 API 明确要求时才转换，并记录不可避免的边界。后续若改宽色域工作原色，必须升级管线版本，不能只改 ICC 标签。
- PhotoCraft 的 RGB 滤镜不因文档带 ICC 就自动具备场景线性或 HDR 语义。按其输入合同适配，不能直接将全部现有滤镜搬到浮点线性缓冲。
- GPU 与 CPU 使用相同参数映射和处理顺序，允许经验证的数值误差；代理尺寸带来的细节差异单独处理。
- JPEG/TIFF 等已显影输入按 ICC 进入处理链，默认保持既有外观，不自动追加 RAW 基础曲线。

### 2.3 胶片与基础呈现的关系

现有胶片资源包含指定的传递函数、色域与明暗呈现，不能在它们前后无条件再叠一次基础曲线。

- 无胶片时，使用所选基础配置生成呈现结果。
- 启用胶片时，基础呈现和胶片分支共享同一份已经调整曝光/白平衡的线性来源；各自按资源合同转换。
- 两个分支在同一声明的显示编码中按胶片强度混合，继承现有胶片强度语义；100% 胶片时由胶片分支决定基础观感，0% 时回到所选基础配置。
- UI 明确显示当前有效风格；100% 胶片时提示基础配置被胶片呈现完全替代，保留所选配置以便关闭胶片后恢复。
- 创意 LUT 是后续调色项，不与相机输入配置、基础呈现、RawLab 胶片资源混为一个列表。
- 统一使用当前显影合同，不维护旧混合、旧滤镜或六色调色兼容分支。

### 2.4 首期基础配置

| 配置 | 目标 | 边界 |
| --- | --- | --- |
| 标准（新 RAW 默认） | 自然颜色、适度对比、平滑高光，适合作为日常起点 | 不做强烈胶片偏色，不默认启用 AI 自动调色 |
| 柔和 | 较低对比、更柔和的明暗过渡，方便人像等场景起步 | 不依赖人物识别，不保证自动美肤 |
| 中性 | 减少风格化、保留手动调整空间 | 仍有必要的显示映射，不直接展示未映射的传感器数据 |

首期不预先堆叠“鲜艳、人像、风景”等大量名称。三套配置的曲线、色彩映射和默认细节处理需要在照片样本上确定，文档不凭空指定看似精确的参数。

基础配置与曝光等手动滑杆独立，切换不覆盖用户已做调整。基础锐化/降噪若启用，要有可见、可关闭的独立设置，并明确与手动细节参数的关系，避免双重处理。

## 3. 配方、默认值与兼容

- 在配方中保存基础配置 ID、版本、管线版本和资源标识；资源内容可变时保存摘要。机型校准来源及引擎版本也进入可复现记录或关联元数据。
- 预览、直方图、剪切提示、取色、保存重开和导出读取同一配方定义；采样工具按其声明阶段取值，不将 JPEG 的统计冒充 RAW 当前结果。
- 全局默认只作用于尚未建立编辑配方的新 RAW；切换全局默认不得改写已有照片。为当前照片切换配置作为一次可撤销操作。
- 不迁移旧配方或旧高级编辑 JSON；当前配方统一处理。历史/快照/虚拟副本用于当前编辑工作流，不用于显影兼容。
- 缓存键加入源文件身份、源版本、解码/校准版本、工作空间合同及必要的配置依赖。基础配置变化只使相关后处理缓存失效，不重新解码 RAW。
- 外部资源缺失或版本不受支持时显示可理解状态，不静默替换为不同风格；导出不得悄悄采用另一套配置。
- 便携方案随带可分发的资源及版本信息；不能携带的资源明确列出依赖。

## 4. 预览与画布

- 打开时显示有效内嵌 JPEG/快速代理，标注“相机预览”；后台生成 RAW 代理，不阻塞初始操作。
- JPEG 已有机内白平衡和风格，不能当作无风格 RAW 再精确套用基础配置。其编辑效果只作为临时近似反馈。
- RAW 候选帧应用最新配方、完整呈现后一次性替换，切换期间保留上一帧；不出现空白、原生窗口边框或焦点抢占。
- 状态区分相机预览、准备 RAW、RAW 预览就绪、失败可重试。颜色判断和最终导出基于 RAW；不通过曝光匹配 JPEG 来冒充统一显影。
- 固定代理用于适屏调色；真正 100% 表示原图像素与显示像素的明确对应，细节面板通过视口/ROI 加载，不能把适屏倍率标成真实 1:1。
- 支持适屏、填充、100%、200%、滚轮缩放、空格临时手形和导航器；切换来源不改变缩放中心、平移、蒙版位置和工具状态。
- 曲线、色轮、裁剪与渐变控制点统一指针捕获、边界处理、失焦取消和撤销事务；一次拖动对应一次撤销。
- 沿用 GPU 优先、CPU 回退、最新请求优先、过期结果淘汰和后台限流；无 GPU 时功能可用，不承诺相同性能。

## 5. 主界面布局

```text
顶部：返回图库 │ 照片名与保存状态 │ 撤销/重做 │ 对比方式 │ 保存编辑 │ 导出
左侧：基础配置 / 预设 / 历史与快照（可切换、可收起）
中央：照片画布 + 必要的工具选项 + 底部缩放/预览状态
右侧：直方图 + 编辑 / 裁剪变换 / 修复 / 蒙版工具区
底部：可收起胶片条，上一张/下一张、星级、旗标、选片状态
```

- 保存编辑只持久化非破坏配方；导出生成成片；返回处理未保存状态。现有“保存成片并返回”拆开，避免一个按钮隐藏多种动作。
- 引入配方自动保存及保存中/已保存/失败重试；关闭窗口和切图遵循同一保存规则。自动保存不因导出失败丢失编辑。
- 导出统一入口；已有进度、取消与强制退出能力保留并完善，不列成从零建设。
- 左右面板可调整宽度和收起，保留用户偏好；全屏、隐藏面板、暗背景查看放在视图操作中。
- 对比支持按住查看、左右并排和分割；区分未编辑 RAW、相机预览和指定历史状态作为参考，保持相同缩放与几何语义。
- 胶片条切图复用当前图库范围，允许星级、旗标及批量同步；切换前完成安全保存，预加载受内存预算约束。

## 7. 常规功能与上游复用边界

优先复用 PhotoCraft 的曲线、八色 HSL、分级、普通锐化/降噪、颜色与亮度范围、蒙版布尔组合、仿制/修复/红眼、手动镜头/透视、ICC 软打样、HDR 与全景算法。上游存在实现不代表已在本应用达到 Lightroom 的效果或性能。

以下需要额外接入或专项开发：

- 完整 WB：原照/自动/Kelvin/预设/吸管，传感器白平衡与 RGB 相对调色分清；曝光/白平衡不可重复应用。
- 自动色调：先复用已有直方图能力；若自动填写多个基础滑杆，另做参数估计，保留一次撤销。
- 镜头：优先评估 RawLab 的数据库接口与校准资源；PhotoCraft 通用焦距模型不能冒充真实镜头配置。去紫边与横向色差校正分别验收。
- 透视：手动/引导式先接已有几何能力，自动 Upright 的线条检测与构图策略后续补。
- Point Color、RGB 原色校准、宠物眼：已有能力只作为基础，分别补齐参数与算法，不宣称直接接界面即可。
- 历史持久化、命名快照、虚拟副本、选择性复制粘贴、上一张参数、批量同步与自动同步由应用层负责；几何和蒙版跨照片同步有明确选择项。
- ICC 软打样与色域提示接上游，增加纸白、黑墨模拟及校样副本；显示器配置路径需平台核对。
- 外部编辑器往返使用受管理的派生成片/资产关系，保留原片与当前配方。

## 8. AI 与合成后续范围

- 主体/背景：评估 BiRefNet；点选/框选物体：评估 SAM 2.1；天空/风景：评估场景分割；人物部位：人体解析与人脸解析组合。均为候选，不是已确定的质量或性能承诺。
- SAM 3 可作文字选择候选，单独核对其许可与部署成本，不沿用 SAM 2 的许可结论。
- 首期先交付稳定的普通蒙版交互；AI 产生蒙版后复用同一套添加、减去、相交、反选和羽化编辑。
- 模型按需安装、本地推理优先、按硬件选择 GPU/CPU、可取消且结果缓存。原图不因智能选择默认上传云端。
- AI 降噪、RAW 细节增强、超分、生成式移除、反射移除、自动深度/镜头模糊分别立项，不把普通滤镜改名为 AI。
- HDR 合成、全景、HDR 全景复用上游基础，补齐输入管理、预览、失败反馈与取消；边界变形需专项实现。
- 真正 HDR 编辑/显示/输出单独验证系统、屏幕、窗口和编码链路，与 HDR 多图合成分开。

## 9. 导出与交付

- 合并高级编辑导出设置：目标位置/相册、格式、尺寸、质量、色彩空间、位深、元数据、文件名及冲突处理。
- 补文件名模板/序号、不放大选项、TIFF 压缩、GPS 移除、版权与关键词、输出锐化、水印及导出预设；只呈现编码器实际支持的选项。
- 相册支持搜索与最近使用；完成后可定位文件或查看成片，不依赖隐藏默认路径。
- 导出进度明确区分解码、显影、合成、编码、写入；无法准确估算时显示阶段状态，不伪造百分比。
- 保留取消、进程隔离/超时与强制退出；取消不登记半成品，重启清理临时文件。强制退出不承诺保存尚未持久化的最后一次输入。
- RAW 原件不可用时可继续查看缓存和编辑配方；完整质量导出明确等待/失败，不静默以相机 JPEG 代替 RAW。

## 10. 实施批次与出口

| 批次 | 内容 | 完成条件 |
| --- | --- | --- |
| A：色彩与配方基础 | 统一 RAW 来源、三种基础配置、版本/缓存、历史配方兼容、JPEG/RAW 状态 | 胶片开关不换解码器；同配方预览/导出顺序一致；重开不变色；旧配方不被默认升级 |
| B：日常编辑界面 | 顶部动作、左右面板、配置浏览、自动保存、缩放/导航、曲线/色轮/蒙版/裁剪交互 | 用户能明确保存与导出的区别；拖动不丢失；模态/焦点不使画布空白或显边框 |
| C：常规工具与交付 | 完整 WB/自动色调、八色 HSL、修复、镜头/透视、历史/快照/副本、复制同步、统一导出 | 逐项补齐真实能力和取消语义；后台失败不丢配方；细节检查使用有效原尺寸数据 |
| D：精确检查与多图 | 软打样、参考图、进阶 Point Color/校准、外部编辑器、HDR/全景 | 明确输入条件和质量边界，预览/输出可对照，失败可恢复 |
| E：AI 与 HDR 扩展 | 智能蒙版、人物部位、增强/消除、深度与真实 HDR | 模型质量、硬件成本、许可和平台支持逐项验收，未完成不宣称支持 |

A 的配方和色彩合同先确定；B 中不依赖渲染的布局整理可随后独立推进。C–E 按子功能逐批交付，不等待整套 Lightroom 清单全部完成。

## 11. 后续验收清单
