# 高级编辑器 Roadmap

更新时间：2026-10-09。基线：Photographer `dd657ad`；PhotoCraft workspace 0.5.0，固定提交 `3955bf4f1911a69ea08947634b3e2b459feece2f`。

目标是逐步接入 PhotoCraft 中适合照片工作流的全部能力，并利用自有 UI 做好选片、调色、精修、合成和交付之间的衔接。功能多时通过工作区、搜索和上下文操作组织，不把所有按钮同时摆在照片周围。高级编辑继续使用独立原生窗口；简单编辑保留。

本文是待实施计划，只有“当前基线”属于已有接线。上游有命令或模块不等于效果、性能和跨平台支持已在本应用验证。阶段按依赖排序，不承诺日期；实施时将条目拆成可验收任务。

## 1. 当前基线与接入原则

当前已接入原生导入、RAW 传感器解码/显影、曝光/白平衡、基础调色、色阶、六色 HSL、RGB/亮度曲线及黑灰白点取色、裁剪/90° 旋转、文字/笔迹、GPU 优先合成与 CPU 回退。已有按住对比、主图库拖入切换、编辑状态保存、成片导回相册/图库和独立窗口。

性能基础为 800 像素交互代理、1600 像素精细预览、两个分别限流的请求通道、RAW 数据及相同显影参数缓存、GPU 缓存和行带读回。预览现已接入持久原生 Session、稳定调整层 ID、显影/几何/标注阶段缓存、帧解码复用、修订号淘汰与分段耗时，见 [预览性能优化](../plans/2026-10-09-editor-preview-performance.md)。这只是代理预览会话，不代表 R2 的原尺寸编辑母版、事务历史和无损持久化已经完成。当前并非全链路 GPU，也没有完整图层工作区、1:1 原尺寸区域预览、完整 Camera Raw 控件或原生文档持久化。

实施原则：

- 应用负责 UI、资产身份、工作流、缓存、调度、任务和存储适配；解码、显影、合成、几何和色彩算法优先调用上游原生 API。
- 允许把上游实现中的代理预览、局部处理和缓存逻辑适配到应用侧，以改善交互；保留算法、工作色彩空间和参数语义，记录来源与许可。算法变更优先在上游处理，不维护第二套调色实现。
- 新工具直接围绕完整原生语义设计：先有文档/图层/蒙版模型，再做工具；不先用扁平 JPEG 或浏览器滤镜模拟，再推倒重来。
- 所有输入照片来自库/资产引用。外部素材通过受管理的导入流程加入；路径解析只在后台。PSD/原生项目是导入导出的交换形式，不成为主流程的文件管理界面。
- 默认拖入另一张照片仍为“打开这张照片编辑”。在明确的合成工具或“添加为图层”操作中，才加入当前文档。
- 保留原片；保存编辑、生成成片、覆盖某个既有成片版本必须是不同语义。跨库、缺源、源替换和相册失效都通过资产适配层处理。

## 2. PhotoCraft 模块接入地图

标记：**已接部分**＝本应用已有调用；**待接原生**＝固定版本源码有对应实现；**需专项验证**＝仍有质量、平台或兼容边界。它们都不表示已经完成本应用验收。

## 3. 实施阶段与验收出口

### R0：响应、正确性与诊断基础

现阶段保留 WebView 画布。原生画布没有必然的显著收益，先收集分段数据，再决定是否值得投入跨平台绘制桥接。已有 frame-ready 与后台各阶段计时，真正呈现时刻和实机性能基线仍待验证。

- [ ] 记录输入到可见帧的分段时间：UI 事件、排队、显影/滤镜、合成、ICC、编码、传输、浏览器解码和展示；冷/热加载分别计时。
- [ ] 建立 1:1 区域预览、分辨率金字塔和视口优先瓦片更新；大图缩放/平移不触发整图重显影。
- [ ] 快速调色只替换最新参数；同一会话的高质量请求合并/取消。上游支持协作取消时传播取消；不支持时隔离并丢弃结果，不能声称后台计算已经停止。
- [ ] 优先前台交互，后台导出/合成限制并发和 CPU 工作线程；区分“可立即 CPU 回退”和“回退会争抢资源”的情况。
- [ ] 预算覆盖 RAW、文档瓦片、历史、代理、GPU、读回、Blob 和浏览器图像；按可用内存调整，而非只限制缓存条目数。
- [ ] 放大取色/检查细节来自高位深区域，不依赖 JPEG 代理；支持剪切提示、采样半径和固定取样点。
- [ ] 验证字体、旋转/裁剪坐标、透明度、ICC、GPU/CPU 和预览/成片一致性，明确 RAW 内嵌预览兜底。
- [ ] 审计每个原生滤镜的颜色编码假设：例如 Camera Raw RGB 核函数注明使用 sRGB 编码，RAW 原生显影输出 ProPhoto。工作空间转换必须按原生接口完成，不能将保留 ICC 等同于所有滤镜已正确处理该 ICC。

验收出口：先在 Windows/macOS 记录 24/45/100 MP、8/16/32 位、不同 GPU 和 CPU 回退环境的基线。初始交互目标为常用调色暖缓存输入到可见帧 p95 ≤ 50ms；属于待实测的目标，不是当前性能承诺。慢操作保持 UI 可操作，并能看到进度、取消或切换；不要求每个重滤镜实时达到同一目标。

### R1：完整摄影调色与镜头几何

- [ ] 接入完整 Camera Raw 基础、细节、效果、参数曲线、八色混色器和色轮。
- [ ] 高光/阴影剪切查看，锐化/降噪 1:1 对照，Alt 显示蒙版/影响区域；控件重置、双击归零、精调和键盘输入统一。
- [ ] 镜头校正、任意角旋转、水平/垂直线校正和广角约束；保存校正顺序及边界填充规则。
- [ ] 黑白混色、LUT、渐变映射、可选颜色等扩展调色，以及可分组/收藏的预设。
- [ ] 基础调色与高级调整层曲线区分原生插值语义，避免错误声称两类曲线算法相同。

验收出口：所有参数可保存/恢复/撤销，实时代理与最终输出顺序一致；处理 RAW/JPEG/TIFF 时明确真实显影阶段。调色预设可以只应用选中的模块，不覆盖裁剪、蒙版或标注。

### R2：完整文档、图层与可靠保存

- [ ] 引入长期后台编辑会话和原生 Document；稳定的图层/蒙版/滤镜 ID、只读查询 DTO、命令事务、增量状态同步。
- [ ] 图层组、调整/填充层、排序/显隐/锁定、混合/不透明度、剪贴关系；图层复合和可切换方案。
- [ ] 用 `.pcraft` 保存完整文档、瓦片、蒙版和智能对象；原子提交、自动保存、恢复及缺源检查。
- [ ] v1 配方迁移到原生文档，并保留原记录和恢复入口；重开不必从完整历史重放全部像素操作。
- [ ] 会话内以一套事务历史管理撤销，拖动一笔/一次手势为一步；应用方案版本与原生 undo 各自职责明确，避免双重撤销栈。
- [ ] 多照片/素材作为受管理的图层依赖，记录原资产及修订；源被移动或失效时使用既有缺源流程。

验收出口：真实多图层编辑关闭重开后完整恢复；历史/蒙版不会被 4MB 配方上限或 JSON 像素数组限制。存储路径与登记规则通过照片库存储模块公开接口接入，先与其负责人对齐契约，不直接增加第二套资产数据库。

### R3：局部调整、选区和蒙版

- [ ] 原生选区与边缘细化工作区；添加/减去/相交、反相、羽化、密度、命名和显隐。
- [ ] 调整层配像素/矢量蒙版：局部曝光、白平衡、HSL、曲线、清晰度等。
- [ ] 画笔、线性/径向渐变、颜色/亮度范围的局部调整交互；源代码有对应能力时复用，没有时标记为扩展依赖。
- [ ] 主体/对象/焦点等自动选区允许继续人工修正；同一蒙版可用于多个调整。
- [ ] 半透明彩色覆盖、仅看蒙版、黑/白背景检查，鼠标唤醒的工具提示；不遮挡照片的常驻输入框。

验收出口：蒙版可以保存、重排、禁用、复用，代理尺度与原尺寸一致，边缘和选区限制在成片中一致。必须建立在 R2 文档模型上。

### R4：精修、变形与智能滤镜

- [ ] 克隆、污点修复、修复画笔、修补、内容识别填充/移动、红眼和局部减淡/加深。
- [ ] 实时画笔轨迹、Alt 取源、取源覆盖、笔刷半径/硬度快捷调节、压力/倾斜；单笔取消/撤销。
- [ ] 采用智能对象/非破坏滤镜；滤镜开关、顺序、参数再编辑及原生可支持的蒙版。
- [ ] 液化、网格变形、透视、木偶和消失点，保存变形数据，不只保存变形后平面像素。
- [ ] 摄影常用模糊/锐化/降噪优先，之后接入完整创意滤镜库。重操作代理预览与原尺寸后台提交分离。

验收出口：精修和变形关闭重开仍可恢复，采样源可定位；慢工具不会把主窗口或编辑窗口卡死。上游缺失的实时预览不能只用静态参数弹窗代替完成验收。

### R5：多照片计算摄影

- [ ] 从图库/相册多选进入全景、HDR、景深堆栈及堆栈运算；素材以照片胶片带组织。
- [ ] 自动建议组：连拍、包围曝光、相邻取景。建议由元数据/现有索引产生，用户确认后才处理。
- [ ] 原生对齐/混合，显示失败照片、参照照片、残差/覆盖范围和输出边界；提供手工调整入口。
- [ ] HDR 输出区分浮点母版、SDR 色调映射成片和实际 HDR 显示；曝光/ICC 统一处理。
- [ ] 扫描照片自动分割/校正、批量生成独立资产；成片登记保留全部来源关联。

验收出口：多源任务可追踪、重试、取消，原片无覆盖；从照片 ID 解析到原生 Document 后调用 `useOpenDocuments` 或原生算法 API，不让用户填路径列表。

### R6：专业输出、版式和互通

- [ ] 分层 PSD/PSB/原生项目交换；导入兼容警告、导出丢失能力清单及字体替换提示。
- [ ] TIFF/PNG/WebP/EXR 等输出按原生读写支持开放；位深、透明背景、ICC、尺寸、质量和元数据策略统一。
- [ ] 软打样、色域警告、输出锐化、打印尺寸/DPI；打印本身根据平台原生能力单独接入。
- [ ] 文字/段落、矢量、图层样式、画板/框架，用于水印、边框、拼图和交付模板。
- [ ] 一次生成多规格成片，导回相册/交付子组；每个结果记录规格和来源方案。

验收出口：编辑母版与交付成片语义明确。输出能力矩阵按格式×平台×读写×位深验证；含 PSD 特殊能力时不承诺与 Photoshop 完全往返。

### R7：自动化、特色工作流与长尾覆盖

- [ ] 原生动作录制/回放、批处理、变量模板；参数和素材引用绑定到资产，而非本地路径。
- [ ] 插件/预设目录、版本、收藏、搜索、依赖诊断；按原生 WASM 限制运行。
- [ ] 可选自动化 API/MCP 提供照片库上下文、命令预览、确认/撤销和任务状态，不直接照搬独立软件的全路径权限。
- [ ] 从引擎命令注册表生成能力目录，逐项补齐摄影、绘画、创意滤镜、矢量、样式、通道和模板工具；核心工具用定制 UI，长尾工具集中在可搜索目录。
- [ ] 每个候选功能记录原生命令、UI、状态保存、性能、格式兼容和验收情况，做到可盘点的覆盖率。

验收出口：“能加的都加”以完整能力登记表持续推进。上游的视频/时间线、独立文件浏览器、扫描仪/系统壳、网页切片等不直接塞进当前纯照片工作流；若未来扩产品范围，再建立对应工作区与资产契约。

阶段依赖：R0 持续贯穿所有阶段；R1 可与 R2 并行推进；R3/R4/R5 依赖 R2；R6 的多规格平面输出可提前，分层互通依赖 R2；R7 的预设与部分批处理可提前，完整动作依赖稳定命令事务。

## 4. 自有 UI 的特色功能

以下是产品设计提案，不是 PhotoCraft 已自带功能。像素算法仍交给原生模块；UI、组织和任务由应用实现。

| 特色功能 | 使用场景和交互 | 技术依赖 / 阶段 |
|---|---|---|
| 相册胶片带与下一张 | 保持筛选、排序、当前子组；快捷键切换，提前准备邻近照片，返回时定位原选片 | 资产查询/缓存，R0/R1；预取预算低于前台 |
| 参考照片调色 | 从图库固定一张参考，双栏/分屏/按住对照；可匹配颜色或只复制选中参数 | 原生 Match Color 与参数同步，R1；参考图不是处理后的标尺，避免强制匹配曝光 |
| 按模块复制、同步、粘贴 | 只复制白平衡/颜色/锐化等；应用到多选照片前预览，裁剪/局部蒙版默认不跟随 | 稳定配方/原生命令、后台任务，R1/R7 |
| 连拍组快速处理 | 一张精调，同组同步；异曝光/异相机照片提示差异，允许单张例外 | 既有照片分组/元数据，R1/R7；不重写图库索引 |
| 方案分支与版本对比 | “自然 / 黑白 / 胶片 / 客户版”均从同一原片出发；不先生成一堆实体 JPEG | 原生文档/图层复合 + 应用版本引用，R2；用户选择生成成片时才登记 |
| 照片上的直接调整 | 点击照片颜色进入目标 HSL/曲线，滚轮微调；Alt 查看影响范围，松开回图 | 高位深采样、原生调色/蒙版，R1/R3；颜色范围算法缺口单独实现接入 |
| 细节检查点 | 固定眼睛、发丝、暗部等多个 1:1 小窗口，调锐化/降噪时同步更新 | ROI 预览，R0/R1；手动点位先可用，自动定位再复用现有人脸信息 |
| 精修检查清单 | “灰尘、红眼、边缘、过曝”等标注可跳转；完成后隐藏标记 | 应用标记层 + 原生修复，R4；质量建议与真实修复效果分开 |
| 素材托盘 | 从相册选背景、Logo、水印；进入合成工具后显式添加图层，显示来源 | 受管理资产依赖、智能对象，R2/R4 |
| 单次处理多种构图 | 同一调色母版生成横版/竖版/方图，各自裁剪可回调；主体位置建议可手动纠正 | 方案版本、原生几何/输出，R2/R6；自动构图额外模型可选 |
| 智能交付 | 相册/客户/子组预设输出规格、水印、ICC 与元数据；一次生成并归组 | 原生文本/输出 + 现有导出登记，R6/R7 |
| 编辑原因与来源追踪 | 成片可跳回原片、方案、使用的素材及同步来源；更新原方案时提示哪些成片过期 | 存储公开契约，R2/R6；需与照片库存储重构协调 |
| 预设的直观选择 | 小图预览、悬停查看、强度滑块、收藏；选择后展开实际改动参数 | 原生预设/混合语义，R1/R7；只低优先级渲染可见预设，不一次跑全部 |
| 无障碍与高效键盘 | 命令搜索、快捷键、焦点导航、紧凑/舒适密度、读屏参数反馈 | UI 基础，贯穿阶段；不以鼠标悬停作为唯一入口 |
| 任务不挡操作 | 合成/批处理走任务中心，用户继续浏览其他照片；完成提醒能回到结果 | 现有任务系统 + 编辑会话资源管理，R0/R5/R7 |

## 5. 界面组织：功能完整，常用操作简洁

采用“浏览/选片 → 调色 → 局部/精修 → 合成 → 输出”的工作区切换，每个工作区只展示相关工具。中央始终是照片；右侧是一组上下文属性面板，图层、历史、参考和胶片带按需展开，允许收藏常用工具。

- 顶部只保留照片上下文、方案状态、保存/生成成片等关键动作；标题/对比/视图操作使用渐变浮层、自动隐藏和鼠标唤醒，也支持键盘唤醒。
- 一个工具图标可以有可搜索的同类工具菜单；长尾滤镜通过命令搜索和分类目录访问，不能每加一个功能就加一个常驻按钮。
- 面板使用紧凑行、折叠分组、数值内联编辑、双击归零与共享快捷操作；高级参数渐进展开。
- 曲线、色轮、蒙版、取源、透视线和裁剪采用画布直接交互；独立弹窗只用于必须集中决策的操作。
- 切换照片与添加合成素材必须能分辨；拖入默认打开，合成模式提供明确落点和动作提示。
- 自动隐藏不用于未保存提示、失败消息或长任务进度。深浅色主题保留中性画布，颜色判断不被界面颜色干扰。

## 6. 架构与性能约束

R2 是扩功能的关键架构点：当前从配方重建文档的方案适合少量全局调整，不适合每次笔刷都重放所有精修历史。新架构持有原生会话/Document，用命令事务和 COW 快照更新；UI 获取精简结构 DTO 与预览瓦片，避免整图层文档往返 IPC。

建议接口按职责拆为：编辑会话、资产源解析、文档查询、工具事务、预览调度、原生处理、持久化、输出任务。照片库只通过公开资产读取和成片登记接口参与；不在引擎接入层直接操作 SQL 或照片落位。

每个工具必须登记：

| 契约 | 必须明确的内容 |
|---|---|
| 参数 | 原生命令/API、单位、范围、默认值、UI 与上游语义转换、校验及版本 |
| 文档 | 生效图层/选区、色彩模式/位深、非破坏能力、栅格化条件、撤销事务 |
| 预览 | 代理/区域策略、半径与坐标缩放、边缘 halo、GPU 支持、回退条件 |
| 任务 | 交互/后台优先级、并发/内存、进度、取消真实能力、过期结果处理 |
| 保存 | 配方/Document 序列化、引用素材、缺失依赖、自动保存/恢复 |
| 输出 | 原尺寸算法和顺序、格式兼容警告、元数据、来源登记 |
| 验收 | 代表照片、边界输入、预览/输出一致性、CPU/GPU、Windows/macOS 和性能基线 |

重滤镜只有原生 CPU 路径时可以先用代理/ROI 和后台任务，不能包装成“GPU 全加速”。不支持取消的内核不能靠关闭窗口假装停止。新接入不得以永久降低成片质量换取代理响应；暂时降代理质量应能自动回到精细结果。

## 7. 需要额外方案、不能直接承诺的能力

- AI 人像/天空/头发分割、语义蒙版、智能人像修复：当前主体选区算法不能替代专用模型；另行选择可嵌入模块，并复用应用推理资源管理。
- AI 去噪、超分辨率、生成式消除/扩图/换背景、自动补睁眼：不能因为上游 roadmap 写了 neural/smart 就当固定 crate 已提供成熟实现。
- 实测镜头数据库、DCP 相机配置、自动镜头匹配和完整相机颜色标定：核对上游现状、数据许可及 API，不能以通用焦距模型代替。
- 真实 HDR 屏幕输出：需要系统、窗口及显示链路支持；SDR WebView 的 HDR 预览不能冒充 HDR 显示。
- Photoshop 全格式/智能滤镜往返：上游仍有 partial/missing 项及导出警告，按实际能力提示。
- 所有功能均实时/全部 GPU：上游自身性能 scorecard 仍有超预算及未测场景；自己的 UI 和调度可改进，但不能照搬其宣传或目标当实测结果。

这些条目保留在能力目录中，标为“额外依赖 / 待上游 / 待验证”，不删除长期目标，也不显示不可用的空控件。

## 8. 开始实施时的最小任务包

1. R0：分段性能指标 + 1:1 区域预览 + 交互/后台调度验证。
2. R1：完整 Camera Raw 参数契约与紧凑摄影面板；每个参数有对应原生命令/默认值/保存规则。
3. R2：原生会话与文档 DTO、`.pcraft` 持久化、v1 迁移、图层基础面板。
4. R3：选区、局部蒙版、画笔/渐变调整；之后 R4 精修与智能滤镜。
5. R5/R6：多图合成和专业输出；R7 覆盖长尾及自动化。

每个任务包完成后更新本文勾选、实际验收结果和限制。按当前约定，本次仅写文档，不运行构建或测试；本次没有得到实机性能或效果验证结果。代码变更按会话要求提交，只有用户要求时推送。
