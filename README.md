# 📷 Photographer

**把照片好好存下来，随时找得到，也能顺畅完成拍摄到交付。**

Photographer 是一款照片存档、搜索和管理应用，也服务于摄影师从拍摄、选片到交付的工作流。当前处于 `0.1.0-alpha` 开发阶段，已具备本地照片库、相册、选片、AI 索引、基础编辑和联机拍摄等功能；网盘交付、移动端和多人协作仍在规划中。

> 🧭 **关于进度**：以下按当前仓库代码整理（2026-10-08）。已实现表示已有代码和操作入口；相机兼容性、平台支持及实际使用效果仍需设备验证。

## ✨ 想解决什么问题

照片会越积越多，散落在相机卡、电脑、硬盘和 NAS 上，时间久了很难找回。Photographer 希望成为长期使用的照片库：安全存档、避免重复、按相册和条件搜索，清楚地管理原片与成片。当前只处理照片和 RAW，视频文件不会导入或显示。

摄影工作流也是这个照片库的一部分：导入 RAW/JPEG、选片、交给 Lightroom Classic 调色、找回成片并交付，让每一步的照片都能对应得上。

需要完成一次拍摄任务时，流程可以是：

```text
连接相机或选择文件夹
→ 创建相册并导入照片
→ 需要时借助 AI 或手动选片
→ 在 Lightroom Classic 中调色
→ 导回成片，与原片放在一起管理
→ 选择照片发布到网盘并分享
```

选片和 AI 分析都可以稍后再做。只想先把照片安全导入相册，也可以直接完成导入。

### 里程碑 01 · 🗂️ 存档与查找

- 从相机、读卡器或本地文件夹导入；既可自动导入，也可只挑选相机里的部分照片。
- 每次导入都能新建或选择相册，并按日期和相册名称整理到指定目录。
- 自由选择导入 RAW、JPEG 或两者；再次遇到已经导入的文件时，按用户设置跳过、询问或保留副本。
- 在“所有照片”和“相册照片”中按日期、格式、星级、标签、人物等条件查找。照片在 NAS 上暂时无法访问时，仍能查看已缓存的信息和缩略图。
- 长期保留照片来源和原片、成片之间的关系，方便日后重新查找与整理。

### 里程碑 02 · ⭐ 选片与成片

- 在相册里随时选片：快速浏览、对比、打星、打标、批量筛选，把未保留的照片从相册中排除或安全删除。
- 可选择在导入时建立 AI 索引，也可之后手动为某个相册或选中的照片建立索引。AI 帮助找人物、疑似闭眼、疑似失焦和相似连拍；最终选择由用户决定。
- 将可互通的星级等信息写入 XMP，方便在 Lightroom Classic 中继续筛选。
- 把 Lightroom Classic 导出的 JPEG 导回应用，关联对应原片；一键切换“原片”“成片”和两者对照，也能管理同一原片的多个成片版本。

### 里程碑 03 · 📷 拍摄与编辑

- 逐步支持更多相机的联机拍摄与自动接收新照片。不同相机能提供的拍摄控制、实时预览和文件传输能力会有所不同；支持情况以实际测试结果为准。
- 在应用内预览照片与 RAW。
- 提供裁剪、文字和画笔标注、调整输出尺寸、编辑元数据及导出 JPEG。原片保留，编辑结果作为新版本管理。

### 里程碑 04 · 📱 手机与 iPad

- **手机**侧重查看相册、少量导入、查看交付内容，以及使用摄像头为胶片摄影提供反射式测光建议；不以大批量选片为主要场景。
- **iPad**侧重拍摄现场：连接已支持的相机，接收和预览新照片，选择相册与导入格式。需要时可以简单打星；完整选片可以稍后在桌面端完成。
- iPad 现场导入可以先跳过 AI 分析，之后再手动建立索引。手机测光会提供胶卷 ISO、光圈/快门换算和校准设置；测量效果需要按设备验证。

### 里程碑 05 · ☁️ 分享交付

- 手动选择原片、成片或指定版本发布到网盘，查看上传进度，并保存分享链接和交付记录。
- 优先探索百度网盘交付，再逐步扩展其他渠道；能否自动生成分享链接取决于相应平台提供的接口。没有合适接口时，可先导出交付文件夹，再由网盘官方客户端上传。

### 里程碑 06 · 🤝 多人协作

- 计划让团队成员共享照片库或相册，在有权限的范围内一起查看、整理和选片。
- 协作时能看清照片是谁导入、修改或标记的，减少重复劳动和改动冲突。具体协作方式会在这一阶段明确。

## 🧩 我们坚持的做法

- **原片优先**：日常可把原片放在本地硬盘或 NAS，缩略图和索引留在速度更快的本机存储中。
- **长期可找**：相册、搜索、元数据和原片/成片关系都是照片档案的一部分。
- **操作可控**：AI 只给出建议；导入、选片、删除和网盘发布都让用户看得清、改得回。
- **尊重现有工具**：Photographer 负责整理与衔接，不要求用它取代 Lightroom Classic 的调色流程。
- **逐步验证兼容性**：相机、手机、RAW 格式和网盘服务的支持范围以真实设备和实际接口测试为准。

开发人员可阅读 [详细实现计划](docs/implementation-plan.md)，其中包含数据关系、导入与去重规则、相机适配、AI、性能、许可风险和各阶段验收方式。

## 开发环境

- Windows 10 21H2+；Node 26（用户级 `~/.local/nodejs`）、Rust stable（MSVC）+ VS Build Tools
- Git Bash 中先加载工具链：`source .tools/env.sh`（npm 源已配置 npmmirror）

## 常用命令

```bash
source .tools/env.sh        # 每个新 shell 先执行
npm run tauri dev           # 开发运行（热更新）
npm test                    # 前端 vitest 全量测试
npm run build               # 前端类型检查 + 构建
cd src-tauri
cargo test                  # Rust 单测+集成测试
cargo clippy --all-targets -- -D warnings
```

## 安装包构建

双击 `scripts\build-installer.cmd`（或仓库根执行）：release 编译后产出 NSIS exe（免管理员）和 WiX msi 到 `installer-output\`。

GitHub 也可以手动构建和发布：进入仓库的 **Actions → Windows build and release → Run workflow**，选择运行模式：

- `build-only`：只构建，在本次运行的 Artifacts 中下载 exe 和 msi（保留 14 天）。
- `draft`：构建后创建或更新 GitHub Release 草稿。
- `publish`：构建后直接创建正式 GitHub Release；若同版本草稿已存在，则更新安装包并发布草稿。

发布标签留空时会使用 `tauri.conf.json` 中的版本号生成（例如 `v0.1.0`）。发布前需同步更新 `package.json`、`src-tauri/Cargo.toml` 和 `src-tauri/tauri.conf.json` 的版本号，工作流会校验三者一致。

代码合并或直接推送到 `main` 后会自动构建，并使用当前应用版本创建或更新正式 Release。因此每次准备发布新版本时，应先递增上述三个文件中的版本号。

推送到 `dev` 时也会自动构建安装包用于验证，但不会创建 Release。

工作流会复用 npm 下载、Rust 依赖与编译产物以及 Tauri 的 NSIS/WiX 打包工具缓存。连续推送到 `dev` 时，旧的未完成构建会自动取消；`dev` 构建产物保留 3 天，正式分支及手动构建保留 14 天。

## 数据目录

- 默认应用数据目录：`%APPDATA%\photohub`；模型与照片库目录以应用设置为准
- 建库时自行选择照片存储目录；支持在设置中迁移库目录，不要求使用特定盘符
- 卸载前确认安装器的数据清理选项，并备份需要保留的照片与库数据
