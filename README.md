# 📷 Photographer

**把照片好好存下来，随时找得到，也能顺畅完成拍摄到交付。**

Photographer 是一款照片存档、搜索和管理应用，也服务于摄影师从拍摄、选片到交付的工作流。当前处于 `0.1.0-alpha` 开发阶段，已具备本地照片库、相册、选片、AI 索引、基础编辑和联机拍摄等功能；网盘交付、移动端和多人协作仍在规划中。

> 🧭 **关于进度**：以下按当前仓库代码整理（2026-10-08）。已实现表示已有代码和操作入口；相机兼容性、平台支持及实际使用效果仍需设备验证。

界面支持在 **设置 → 外观** 中切换浅色和深色主题，并保存选择。深色沿用原有黑色配色，浅色采用中性白灰与磨砂浮层。图库和相册的浏览操作靠近右上角时唤醒，停止操作后自动隐藏；筛选和批量操作按需显示。

预览标题与右侧按钮使用从上方半透明黑色向下渐隐的背景。缩放时，底部显示可拖动的 **100%–400%** 缩放条，右侧显示百分比；停止操作 **3 秒**后隐藏，拖动期间保持显示。这里的 100% 表示当前适应预览区的尺寸。

导入默认采用复制。可靠识别的 SD 卡和相机仅允许复制；外置硬盘、SSD、U 盘与本地文件夹保留引用及移动方式。无法识别介质类型时仍默认复制，也允许手动选择“仅导入”；来源离线时使用已有的缺源提示与缓存浏览能力。

当前桌面端已有 Windows 和 Apple Silicon macOS 适配与打包流程；Linux 和移动端仍待完善，各平台相机能力需分别验证。AI 模型按需管理，相机操作按后端报告的能力显示。

## ✨ 想解决什么问题

照片会越积越多，散落在相机卡、电脑、硬盘和 NAS 上，时间久了很难找回。Photographer 希望成为长期使用的照片库：安全存档、避免重复、按相册和条件搜索，清楚地管理原片与成片。当前只处理照片和 RAW，视频文件不会导入或显示。

摄影工作流也是这个照片库的一部分：导入 RAW/JPEG、选片、交给 Lightroom Classic 调色、找回成片并交付，让每一步的照片都能对应得上。

需要完成一次拍摄任务时，流程可以是：

```text
连接相机或选择文件夹
→ 创建相册并导入照片
→ 需要时借助 AI 或手动选片
→ 在 Lightroom Classic 中调色
→ 导回成片，与原片放在一起管理
→ 将选定照片或编辑结果导出到本地目录
```

选片和 AI 分析都可以稍后再做。只想先把照片安全导入相册，也可以直接完成导入。

## 🧩 我们坚持的做法

- **原片优先**：日常可把原片放在本地硬盘或 NAS，缩略图和索引留在速度更快的本机存储中。
- **长期可找**：相册、搜索、元数据和原片/成片关系都是照片档案的一部分。
- **操作可控**：AI 只给出建议；导入、选片、删除和网盘发布都让用户看得清、改得回。
- **尊重现有工具**：Photographer 负责整理与衔接，不要求用它取代 Lightroom Classic 的调色流程。
- **逐步验证兼容性**：相机、手机、RAW 格式和网盘服务的支持范围以真实设备和实际接口测试为准。

## 开发环境

- 通用工具链：Node.js 22.22.2+、npm、Rust stable。
- Windows：MSVC、VS Build Tools、WebView2。
- Apple Silicon macOS：Xcode Command Line Tools，通过 Homebrew 安装 CMake 和 libgphoto2（`brew install cmake libgphoto2`）。
- 原生图片解码依赖 NASM；CI 使用 NASM 3.2.0。确保工具链已加入 PATH。

```bash
npm ci                      # 安装前端依赖

```

## 安装包构建

Windows：

双击 `scripts\build-installer.cmd`（或仓库根执行）：release 编译后产出两种 NSIS exe（免管理员）到 `installer-output\`：精简版在缺少 WebView2 时下载运行时，离线版内置 WebView2。传入 `--online-only` 可只构建精简版。

macOS：`npm run tauri:build:macos -- --target aarch64-apple-darwin` 构建 Apple Silicon 应用和 DMG；相机运行时组装见 `scripts/assemble-gphoto-bundle-macos.sh`，CI 已包含组装步骤。

GitHub 也可以手动构建和发布：进入仓库的 **Actions → Windows build and release / macOS build and release → Run workflow**，选择运行模式：

- `build-only`：只构建，在本次运行的 Artifacts 中下载安装包（dev 保留 3 天，其他分支保留 14 天）。
- `draft`：构建后创建或更新 GitHub Release 草稿。
- `publish`：构建后直接创建正式 GitHub Release；若同版本草稿已存在，则更新安装包并发布草稿。

发布标签留空时会使用 `tauri.conf.json` 中的版本号生成（当前为 `v0.1.0-alpha`）。发布前需同步更新 `package.json`、`src-tauri/Cargo.toml` 和 `src-tauri/tauri.conf.json` 的版本号，工作流会校验三者一致。

代码合并或直接推送到 `main` 后会自动构建，并使用当前应用版本创建或更新正式 Release。因此每次准备发布新版本时，应先递增上述三个文件中的版本号。

推送到 `dev` 时自动构建 Windows 精简版安装包和 macOS DMG，不创建 Release；`main` 另构建 Windows 离线版。

工作流会复用 npm 下载、Rust 依赖与编译产物以及 Tauri 打包工具缓存。连续推送到 `dev` 时，旧的未完成构建会自动取消；`dev` 构建产物保留 3 天，正式分支及手动构建保留 14 天。

## 数据目录

- 默认应用数据目录：`%APPDATA%\photohub`；模型与照片库目录以应用设置为准
- 建库时自行选择照片存储目录；支持在设置中迁移库目录，不要求使用特定盘符
- 卸载前确认安装器的数据清理选项，并备份需要保留的照片与库数据
